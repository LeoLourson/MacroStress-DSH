# Интеграция MacroStress в DeepSeek Harness

Пакет `dsh-macrostress` подключает инструменты MacroStress к агенту DeepSeek Harness (DSH), регистрирует навыки работы и добавляет снимок рабочего каталога в системный промпт. Вычисления выполняет отдельный Python-пакет `mst`; интеграция не содержит собственных моделей. Для подключения к профилю используйте [руководство по установке](<../docs/howto/install.md>), а для параметров вызова — [справочник инструментов](<../docs/reference/tools.md>).

## Из чего состоит пакет

| Файл или каталог | Назначение |
|---|---|
| [Манифест пакета](<package.json>) | Имя, версия, экспорты и ссылка `dsh.bundle.patch` на слой подключения |
| [Слой подключения](<cordis.patch.yml>) | Добавляет MCP-клиент с сервером `macrostress` и сам плагин |
| [Плагин](<index.js>) | Регистрирует навыки и раздел системного промпта; объявляет зависимости `skills` и `systemPrompt` |
| [Строки карточки](<locale/README.md>) | Название и описание пакета на поддерживаемых языках |
| [Набор навыков](<skills/README.md>) | Правила подготовки сценария, чтения отчёта, обновления драйверов и опроса модели |
| [Локальная проверка](<test/smoke.mjs>) | Проверяет регистрацию, снимок, перечитывание состояния, снятие навыков и локали без запуска DSH |

MCP, Model Context Protocol, служит протоколом между клиентом агента и Python-сервером. Поставляемый слой использует транспорт `stdio` и запускает опубликованный пакет командой `uvx --from macrostress>=1.1.0 macrostress`. Путь конкретной машины в общий слой не записывается. Если нужен исходный checkout или другой рабочий каталог, настройки задают в профиле по [руководству установки](<../docs/howto/install.md>), не редактируя общий пакет под одну машину.

## Сервер и снимок должны читать один каталог

Рабочий каталог, или workspace, содержит ряды, версии моделей, сценарии, портфели и результаты. Сервер выбирает каталог через `--workspace`, затем `MACROSTRESS_WORKSPACE`, затем правило поиска по умолчанию. Плагин выбирает `config.workspace`, затем ту же переменную окружения и то же правило поиска. Если серверу передан только `--workspace`, плагину нужно отдельно задать соответствующий каталог: иначе инструменты и снимок могут описывать разные данные.

По умолчанию выбирается первый существующий каталог в таком порядке:

1. `~/.macrostress/workspace`;
2. каталог данных пользователя операционной системы;
3. `./workspace` относительно каталога запуска.

В Windows каталог данных — `%LOCALAPPDATA%/macrostress/workspace`, в macOS — `~/Library/Application Support/macrostress/workspace`, в Linux — `$XDG_DATA_HOME/macrostress/workspace` либо `~/.local/share/macrostress/workspace`. Если ничего не найдено, сервер создаёт каталог данных пользователя; при невозможности создать его без явного пути пробует локальный `./workspace`. Явно заданный недоступный путь должен завершиться сообщением об ошибке, а не незаметной подменой данных.

Снимок содержит путь, короткие хеши последней макроверсии и совместимых сателлитов, дату индекса корпуса и счётчики портфелей, сценариев, расчётов и незавершённых задач. Раздел занимает пять строк, а при отсутствии снимка — одну строку с предложением вызвать `jobs(action="state")`. Плагин кеширует текст до изменения времени или размера файла; сам вызов `jobs(action="state")` обновляет сведения о завершённых задачах и счётчиках.

## Навыки и срок их действия

Навык — текстовая инструкция агенту о порядке работы, а не новая вычислительная функция. Плагин читает подходящие Markdown-файлы из своего набора, регистрирует их на время включения и снимает при выключении. На 13 ноября 2026 года комплект включает подготовку сценария, чтение результата, работу с драйверами, ответы модели и управление многопользовательским опросом агентов; точные имена и источники перечислены в [описании навыков](<skills/README.md>).

Сервер также отдаёт руководства инструментом `guide`, поэтому порядок работы доступен клиентам без DSH. Состав руководств сервера может расширяться установленными моделями, тогда как набор навыков пакета DSH определяется опубликованными файлами. Совпадение копий проверяется тестами проекта.

## Проверка без графического клиента

Из корня репозитория выполните команду в окружении с Node.js:

```powershell
node dsh/test/smoke.mjs
```

Проверка создаёт собственные временные данные и подставляет контекст регистрации, поэтому не требует рабочего каталога пользователя или запущенного DSH. Она подтверждает состав навыков, пять строк снимка, запасной текст без состояния, перечитывание изменённого файла, снятие регистраций и наличие названия с описанием в обеих локалях.

Успех локальной проверки не подтверждает соединение с реальным Python-сервером и отображение карточки установленного профиля. После подключения отдельно проверьте вызов `jobs(action="state")` и совпадение пути рабочего каталога со снимком. Разделение проверок отличает исправный код регистрации от правильно настроенного окружения пользователя.
