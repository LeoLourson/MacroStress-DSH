# Сценарий из корпуса

Сценарий — файл `workspace/scenarios/<id>.json`: нарратив, ссылки на фрагменты корпуса,
ограничения на пути, движущие шоки, надбавки, горизонт и хеши двух версий моделей. Его
собирают инструментом `scenario`, а не правкой файла.

## 1. Что уже есть

1. `jobs(action="state")` — последние версии макромодели и сателлитов, дата индекса корпуса,
   число сценариев. Повторите, если индекс или версии менялись.
2. `model(kind="macro", action="list")` — версии макромодели; `model(kind="satellites",
   action="list")` — версии сателлитов. Берите сателлиты, у которых `macro` совпадает с
   выбранной макроверсией; чужие сателлиты `scenario validate` отклонит.
3. `model(kind="satellites", action="describe", version=<сателлиты>)` — какие драйверы
   обслуживаются, а какие отклонены и почему. Надбавка на необслуженный драйвер не пройдёт.

## 2. Найти источники

`corpus(action="search", query="...", as_of="YYYY-MM-DD", k=8)` ищет по индексу и не ходит в
сеть. `as_of` — дата расчёта макроверсии: фрагмент, опубликованный позже, сценарий не
увидит. У результата сохраните `chunk_id` — он пойдёт в `sources` сценария.

`corpus(action="get", id=<chunk_id>, as_of=...)` возвращает фрагмент целиком. Цитируйте
только те фрагменты, на которых действительно стоит число или механизм.

## 3. Собрать N, C, D, O

`narrative` — короткое имя сценария (идентификатор, не абзац). Текст — в `sources`.

`constraints` — список `{"terms": [{"variable": ..., "month": ..., "weight": ...}],
"low": ..., "high": ..., "note": "..."}`:

- `month` — 1..`horizon`; месяц 0 — дата расчёта, в ограничении его нет;
- границы — в шкале модели `y = g(X)`. `transform` переменной в
  `src/mst/macro/registry.toml` говорит, какая это шкала: `identity` — собственные единицы
  (ставка, спред), `log100` — `100·ln(X)` (цена, курс, индекс, кредит); `low <= high`;
  `low == high` фиксирует значение;
- одна переменная в одном ограничении встречается один раз; вес не ноль;
- ограничение должно быть выполнимо движущими шоками: `validate` назовёт связку, которую
  шоки не сдвигают.

`driving_shocks` — id шоков макромодели (`src/mst/plugins/bvar/signs.toml`): `ru.monetary`,
`ru.inflation`, `ru.fx_risk`, `gl.oil`, `gl.financial`. Пустой список значит «любой шок».

`overlays` — `{"driver": "<величина>:<объект>", "start": ..., "end": ..., "delta": ...,
"reason": "...", "sources": ["<chunk_id>"]}`:

- `delta` прибавляется к драйверу **в шкале модели** `y = g(d)`, а не в его собственных
  единицах и не в процентах: у `identity` это собственные единицы, у `log100` — `100·ln(d)`
  (падение цены на 10 % это `100·ln(0.9) ≈ −10.54`), у `logit` — `ln(d/(1−d))`. Не пишите
  процентное изменение как `−0.1`;
- `start <= end <= horizon`, `reason` и `sources` обязательны;
- драйвер должен обслуживаться выбранной версией сателлитов.

## 4. Сохранить и проверить

```json
{
  "narrative": "key_rate_hold",
  "sources": ["<chunk_id>"],
  "horizon": 12,
  "macro": "<64 hex>",
  "satellites": "<64 hex>",
  "constraints": [
    {"terms": [{"variable": "ru.key_rate", "month": 1, "weight": 1.0}],
     "low": 21.0, "high": 21.0, "note": "ставка 21 % в первый месяц"}
  ],
  "driving_shocks": ["ru.monetary"],
  "overlays": []
}
```

1. `scenario(action="save", id="key-rate-hold", spec={...})` — проверяет контракт и пишет
   файл. `id` — строчные буквы, цифры и дефис; пробелы и заглавные не годятся.
2. `scenario(action="validate", id="key-rate-hold")` — читает обе версии, проверяет
   выполнимость ограничений, надбавки, хеш сателлитов и видимость фрагментов корпуса. Пока
   `problems` не пуст, сценарий не считается.
3. `scenario(action="get", id=...)` — что записано.

`save` проверяет только контракт; `validate` — то, что сценарий действительно считается.
Не сохраняйте сценарий в обход `scenario`: id файла и id сценария — одно и то же.
