# Сценарий из корпуса

Сценарий — файл `workspace/scenarios/<id>.json`: нарратив, ссылки на фрагменты корпуса,
условия на пути, причины, воздействия, горизонт и хеши двух версий моделей. Его
собирают инструментом `scenario`, а не правкой файла.

## 1. Что уже есть

1. `jobs(action="state")` — последние версии макромодели и сателлитов, дата индекса корпуса,
   число сценариев. Повторите, если индекс или версии менялись.
2. `model(kind="macro", action="list")` — версии макромодели; `model(kind="satellites",
   action="list")` — версии сателлитов. Берите сателлиты, у которых `macro` совпадает с
   выбранной макроверсией; чужие сателлиты `scenario validate` отклонит.
3. `model(kind="satellites", action="describe", version=<сателлиты>)` — какие драйверы
   обслуживаются, а какие отклонены и почему. Надбавка на необслуженный драйвер не пройдёт.

## 2. Найти источники

`corpus(action="search", query="...", as_of="YYYY-MM-DD", k=8)` ищет по индексу и не ходит в
сеть. `as_of` — дата расчёта макроверсии: фрагмент, опубликованный позже, сценарий не
увидит. У результата сохраните `chunk_id` — он пойдёт в `sources` сценария.

`corpus(action="get", id=<chunk_id>, as_of=...)` возвращает фрагмент целиком. Цитируйте
только те фрагменты, на которых действительно стоит число или механизм.

## 3. Собрать N, C, D, O

`narrative` — короткое имя сценария (идентификатор, не абзац). Текст — в `sources`.

`constraints` — список `{"terms": [{"variable": ..., "month": ..., "weight": ...}],
"low"/"high" или "value", "basis": ["<chunk_id>"] | "assumption"}`:

- `month` — 1..`horizon`; месяц 0 — дата расчёта, в ограничении его нет;
- границы — в шкале модели `y = g(X)`. `transform` переменной в
  `src/mst/macro/registry.toml` говорит, какая это шкала: `identity` — собственные единицы
  (ставка, спред), `log100` — `100·ln(X)` (цена, курс, индекс, кредит). Значение задаётся
  либо интервалом `low < high`, либо точным `value` — платформа расширит его до
  `value ± tau` (десятая часть типичного месячного движения); `low == high` запрещено;
- одна переменная в одном ограничении встречается один раз; вес не ноль;
- `basis` обязателен: фрагменты корпуса, на которых стоит условие, или слово `assumption`;
- ограничение должно быть выполнимо причинами: `validate` назовёт связку, которую причины
  не сдвигают.

`causes` — координаты `omega`, через которые сценарий объясняет событие: id шоков
макромодели (`src/mst/plugins/bvar/signs.toml`: `ru.monetary`, `ru.inflation`, `ru.fx_risk`,
`gl.oil`, `gl.financial`) и скрытые координаты, которые модель объявляет (`regime_path` у
MS-VAR, `volatility_path` у BVAR). Пустой список значит «всё, кроме параметров», и это
дешевле по цене: чем меньше причин названо, тем дороже объяснение. Имя режима в `causes` —
это причина («событие объяснено режимом»), а не фиксация; фиксацию задаёт `regime_event`.

`regime_event` — элемент режима, который само событие утверждает (фиксирует на всём
горизонте), например `"regime.stress"` у MS-VAR. Если называете причины и утверждаете
режим, назовите и `regime_path` среди причин.

`approved_by` — кто утвердил сценарий. Пока поле пустое, `validate` отказывается считать
сценарий: по канону человек утверждает его до расчёта.

`impacts` — `{"target": "<величина>:<объект>" или id макропеременной, "start": ..., "end": ...,
"delta": ..., "reason": "...", "basis": ["<chunk_id>"] | "assumption"}`:

- `delta` прибавляется к величине **в шкале модели** её уровня, а не в собственных единицах
  и не в процентах: у `identity` это собственные единицы, у `log100` — `100·ln(d)` (падение
  цены на 10 % это `100·ln(0.9) ≈ −10.54`), у `logit` — `ln(d/(1−d))`. Не пишите процентное
  изменение как `−0.1`;
- адрес — макропеременная уровня 0 (надбавка входит в путь до сателлитов и действует на все
  драйверы, которые её читают) или драйвер; драйвер должен обслуживаться выбранной версией
  сателлитов;
- `start <= end <= horizon`, `reason` и `basis` обязательны; фрагменты в `basis` тоже
  проверяются на видимость по дате расчёта;
- ограничение на ту же переменную, что и надбавка, выполняется по итоговому пути: не
  добавляйте `delta` к `low`/`high` вручную;
- старое поле `overlays` не читается: пишите `impacts` с `target`.

## 4. Сохранить и проверить

```json
{
  "narrative": "key_rate_hold",
  "sources": ["<chunk_id>"],
  "horizon": 12,
  "macro": "<64 hex>",
  "satellites": "<64 hex>",
  "constraints": [
    {"terms": [{"variable": "ru.key_rate", "month": 1, "weight": 1.0}],
     "value": 21.0, "basis": ["<chunk_id>"]}
  ],
  "causes": ["ru.monetary"],
  "impacts": [],
  "approved_by": "И. Иванов"
}
```

1. `scenario(action="save", id="key-rate-hold", spec={...})` — проверяет контракт и пишет
   файл. `id` — строчные буквы, цифры и дефис; пробелы и заглавные не годятся.
2. `scenario(action="validate", id="key-rate-hold")` — читает обе версии, проверяет
   выполнимость ограничений, причины, надбавки, хеш сателлитов, утверждение и видимость
   фрагментов корпуса. Пока `problems` не пуст, сценарий не считается.
3. `scenario(action="get", id=...)` — что записано.

`save` проверяет только контракт; `validate` — то, что сценарий действительно считается.
Не сохраняйте сценарий в обход `scenario`: id файла и id сценария — одно и то же.
