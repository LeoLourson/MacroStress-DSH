# Навыки агента для MacroStress

Навыки пакета `dsh-macrostress` объясняют агенту DeepSeek Harness, в каком порядке готовить сценарий, запускать расчёт и проверять результат. Навык содержит инструкцию, а вычисление выполняется инструментами Python-сервера. Разделение позволяет использовать одинаковый порядок работы в DSH и в другом клиенте через инструмент `guide`.

## Какие задачи покрывает комплект

| Файл навыка | Когда применяется |
|---|---|
| [Подготовка сценария](<scenario-from-corpus.md>) | Событие переводится в вмешательства и наблюдения с источниками, календарём, единицами и утверждением человеком |
| [Расчёт и чтение отчёта](<run-report.md>) | Агент запускает задачу, ждёт завершения и читает квантили, среднюю хвостовую потерю, цену и покрытие |
| [Драйверы и сателлиты](<drivers.md>) | Обновляется каталог объектов, оцениваются сателлиты и разбирается отказ обслуживания драйвера |
| [Ответы модели](<model-inputs.md>) | Агент отвечает на малые вопросы модели с соблюдением единиц и правил публикации |
| [Управление опросом](<elicitation-orchestration.md>) | Ведущий агент распределяет ключи между авторами, читает замечания и возвращает шаги на исправление |

На 13 ноября 2026 года комплект содержит перечисленные файлы. Загрузчик не ограничивает число навыков константой: [плагин](<../index.js>) читает все Markdown-файлы каталога по алфавиту и регистрирует подходящие записи. Название `name` и описание `description` в начальном блоке метаданных, а также непустой текст обязательны; `whenToUse` необязателен.

Начальный блок метаданных отделяется строками `---`; после него идёт текст инструкции. Минимальная форма с необязательным полем `whenToUse`:

```markdown
---
name: example-work
description: Explain a bounded task through MacroStress tools.
whenToUse: Before performing that task.
---

Read the relevant tool contract before acting.
```

Загрузчик применяет простой разбор строк по двоеточию, а не полный обработчик YAML, языка описания структурированных данных. Поэтому многострочные структуры метаданных не следует считать поддерживаемыми. [Описание набора навыков](<README.md>) не содержит начального блока метаданных и не регистрируется как инструкция.

## Где находится исходный текст

Платформенные руководства хранятся в [пакете руководств сервера](<../../src/mst/guides/__init__.py>), а руководства опроса принадлежат [объявлению экспертного плагина](<../../src/mst/plugins/expert/plugin.py>). Копии в DSH нужны потому, что пакет интеграции может устанавливаться отдельно от Python-пакета. Изменение правила следует начинать в источнике и синхронизировать с копией; независимая правка одной копии создаёт разные инструкции для клиентов.

Тексты навыков написаны на английском, поскольку их читает модель; [описание набора навыков](<README.md>) предназначено сопровождающему человеку. Список руководств сервера запрашивается через `guide()` и может расширяться другими установленными плагинами. Такой серверный список не обязан совпадать с набором файлов отдельно установленной версии DSH-интеграции.

## Что проверяется

[Локальная проверка](<../test/smoke.mjs>) регистрирует навыки в подставном контексте, проверяет их имена, непустой текст и удаление регистраций при выключении. Она также проверяет снимок состояния и локали карточки, но не запускает настоящий DSH или численные модели. Команда из корня репозитория:

```powershell
node dsh/test/smoke.mjs
```

При добавлении навыка обновляют ожидаемый список проверки и сохраняют соответствие источнику. Успех регистрации не доказывает, что инструкция экономически верна: предметное правило проверяется вместе с функцией, которой принадлежит руководство.
