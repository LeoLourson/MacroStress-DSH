# ADR 0001: Схемы инструментов описывают каждый параметр и аннотируют каждый инструмент

Дата: 2026-11-03
Статус: принято

## Контекст

JSON Schema инструмента MCP — та часть контракта, которую агент и внешний сканер читают
первой. Восемь инструментов — мультиплексоры с ветвлением по `action`, и их параметры несли
типы, но не описания: клиенту приходилось угадывать, какие аргументы нужны действию и что
они значат. Сканеры, оценивающие определения инструментов, видели 0 % описанных параметров
и никаких MCP-аннотаций.

## Решение

Каждый параметр каждого инструмента несёт `Field(description=...)` — для чего поле, его
формат и с чем оно взаимодействует. Описание поля `action` называет каждое действие, которое
знает диспетчер. Каждый инструмент объявляет `ToolAnnotations`: `guide` — чистое чтение
(`readOnlyHint`), `series` и `corpus` ходят в сеть (`openWorldHint`), `portfolio` умеет
удалять файл (`destructiveHint`), `run start` каждый вызов порождает новый расчёт (без
`idempotentHint`). `tests/test_mcp_schema.py` держит покрытие на 100 % параметров и падает,
когда новое действие не названо в описании его поля.

## Последствия

Клиент больше не угадывает допустимые комбинации аргументов по докстрингу инструмента и
отличает чтение от изменения до вызова. Аннотации описывают инструмент целиком, а не каждое
действие — плата за дизайн мультиплексора: действие разрушительнее подсказки своего
инструмента должно говорить об этом в описании своего поля, как делает `portfolio delete`.
