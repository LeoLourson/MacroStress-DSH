# ADR 0001. Описания параметров и аннотации инструментов

Каждый параметр инструмента MacroStress описывается в JSON Schema, а каждый инструмент объявляет подсказки MCP о чтении, изменении и внешних обращениях. Клиент должен узнать назначение поля до вызова, а не восстанавливать его по ошибке. Требование относится и к новым инструментам: число инструментов не определяет полноту их контрактов.

Дата решения: 2 ноября 2026 года. Статус: принято. ADR, запись архитектурного решения, сохраняет причину выбора и его ограничения; интерфейс действующих вызовов приведён в [справочнике инструментов](<../reference/tools.md>).

## Почему типов недостаточно

Model Context Protocol (MCP) передаёт агенту схему параметров инструмента. Большинство инструментов MacroStress объединяют действия через поле `action`: например, один `portfolio` и читает, и удаляет портфель. Тип `str` для `id` не объясняет, идентификатор какого объекта нужен выбранному действию, а необязательное поле не сообщает, когда действие всё же требует его.

Без описаний клиенту приходится читать исходный код или угадывать сочетания аргументов. Внешний анализ схем также не может отличить локальное чтение от обращения к сети или перезаписи состояния. Описание параметра поэтому считается частью API, а не только пояснением для человека.

## Что принято

Параметры объявляются через `Field(description=...)` в [сервере MCP](<../../src/mst/mcp.py>). Описание называет назначение, формат, значения по умолчанию и связь с другими аргументами. Поле `action` перечисляет действия диспетчера; если имя действия или смысл поля меняются, описание должно измениться вместе с кодом.

Каждый инструмент задаёт `ToolAnnotations`: `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint` и читаемый `title`. Подсказка `readOnlyHint` обозначает чтение без изменения, `destructiveHint` — возможность разрушительного действия, `idempotentHint` — повторяемость эффекта, `openWorldHint` — обращения за пределы локального состояния. Подсказки нужны для предварительного решения клиента, но не ограничивают возможности вызванного кода.

Например, `guide` объявляет чистое локальное чтение, `series` и `corpus` могут обращаться к сети, а `portfolio`, `scenario` и `jobs` допускают перезапись, удаление или остановку процесса. Повторный `run start` создаёт новый расчёт, поэтому инструмент не объявляет идемпотентность, то есть сохранение одного эффекта при повторении запроса.

## Альтернатива и цена выбора

Разделение каждого действия на собственный инструмент дало бы точнее аннотации и отдельную схему обязательных полей. Принят общий инструмент на предметную область: такой интерфейс короче, но аннотация относится ко всему инструменту, а зависимости аргументов дополнительно проверяет диспетчер.

Поэтому описание `save` должно прямо предупреждать о перезаписи, даже если рядом доступны безопасные `list` и `get`. Клиент не должен считать все действия инструмента безопасными только потому, что одно действие читает состояние.

## Как удерживается контракт

[Проверки схем MCP](<../../tests/test_mcp_schema.py>) получают определения зарегистрированных инструментов, проверяют описания параметров, наличие аннотаций и упоминание действий из контрольного перечня. Проверка описания требует не менее 15 символов; такая длина отсекает пустые подписи, но не доказывает правильность объяснения.

Контрольный перечень действий нужно обновлять при расширении диспетчера. Проверка не выводит перечень из всех ветвей программы автоматически, поэтому сверка справочника с исходным кодом остаётся необходимой. На 13 ноября 2026 года сервер регистрирует десять инструментов, включая `elicit` и `interview`; прежнее количество не ограничивает применение решения.
