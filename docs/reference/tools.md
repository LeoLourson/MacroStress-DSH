# Справочник инструментов и команд MacroStress

Сервер MacroStress предоставляет десять инструментов через Model Context Protocol (MCP), протокол вызова функций внешним агентом. Инструменты читают и изменяют рабочий каталог, запускают задачи, сохраняют сценарии и возвращают результаты расчёта. Для вызова выбирают имя инструмента и действие `action`; таблицы определяют, какие параметры нужны действию и что получит клиент.

Источник интерфейса — [сервер `mst.mcp`](<../../src/mst/mcp.py>); структуры сценария и расчёта описаны в [контрактах платформы](<platform.md>). Сервер также отдаёт инструкции клиенту при подключении и промпт `scenario_from_event(event)`, который соединяет текст события с руководством подготовки сценария. Промпт не утверждает сценарий и не запускает расчёт.

## Общие правила вызова

`id` означает идентификатор объекта своего инструмента: ряда, задачи, сценария, портфеля или расчёта. Даты `as_of` имеют формат `YYYY-MM-DD` и ограничивают видимость публикаций. Хеш версии выбирает неизменяемую оценённую модель, тогда как `model_id` выбирает реализацию модели, например `rw.joint`. Установленные идентификаторы моделей нужно получать через `model(kind="catalog", action="list")`.

Долгая операция возвращает `job`, идентификатор задачи, сразу после запуска. Клиент ждёт через `jobs(action="wait", id=...)`; по `running=true` ожидание повторяется, а вывод читается через `jobs(action="log", id=...)`. Закрытие ожидающего вызова не отменяет задачу. Запуск расчёта дополнительно возвращает `run`, идентификатор сохранённого расчёта; `job` и `run` не взаимозаменяемы.

Аргумент, не нужный выбранному действию, не следует передавать: общая схема инструмента не выражает все зависимости между полями. Отсутствующее обязательное значение или неизвестное действие приводит к ошибке с именем параметра или допустимыми действиями. Аннотации MCP описывают инструмент целиком; они не заменяют проверку конкретного действия перед перезаписью или удалением.

## `guide`: получить руководство агента

| Параметры | Результат |
|---|---|
| Без `name` | Список доступных руководств с `name`, `description`, `whenToUse` |
| `name` | Текст названного руководства |

Платформа поставляет `scenario-from-corpus`, `run-report` и `drivers`. Установленные плагины могут добавить руководства через `Plugin.guides`; например, экспертная модель добавляет `model-inputs` и `elicitation-orchestration`. Поэтому каталог `guide()` надёжнее фиксированного числа руководств. Тексты написаны для агента на английском; [навыки DSH](<../../dsh/skills/README.md>) публикуют копии тех же руководств в клиенте.

## `jobs`: состояние и долгие задачи

| `action` | Параметры | Результат |
|---|---|---|
| `state` | Нет | Снимок рабочего каталога; завершает записи исчезнувших процессов и обновляет файл снимка |
| `status` | `id` | Запись задачи, `running` и `exit_code` |
| `log` | `id`, необязательный `tail` | Последние строки вывода; `tail=50` по умолчанию, `0` возвращает весь лог |
| `cancel` | `id` | Останавливает дерево процессов, отмечает отмену и освобождает ресурс |
| `wait` | `id`, необязательный `timeout_sec` | Ждёт завершения до таймаута и возвращает ту же запись, что `status` |

`timeout_sec` измеряется в секундах, по умолчанию равен 30 и допускает значения от 0 до 120. Запись задачи содержит аргументы команды `argv`, идентификатор процесса `pid`, время начала `started`, время завершения `finished` и пометку отмены `cancelled`, если задача отменена. Пока код выхода не записан, `exit_code=null`; такое значение возможно и после принудительной остановки. Поэтому отсутствие кода выхода не означает успешного завершения.

Задачи блокируют ресурсы `series`, `models`, `corpus`, `code`, `runs`. На одном ресурсе одновременно работает одна задача; новый запуск получает `ResourceBusy`, если держатель жив. Подробности ожидания и восстановления записей описаны в [решении о `jobs wait`](<../adr/0002-job-wait.md>).

## `series`: исторические ряды

| `action` | Параметры | Результат |
|---|---|---|
| `search` | `text` | Источники, у которых идентификатор или имя загрузчика содержит текст |
| `get` | `id`, необязательный `as_of` | Значения, известные на дату; без `as_of` используется сегодняшний день |
| `add` | `entry` | Проверяет новый источник и записывает его в пользовательские источники |
| `update` | Необязательный `ids` | Запускает загрузку рядов на ресурсе `series`; без списка загружает все известные источники |
| `update` | `quantity` вместо `ids` | Находит объекты величины и загружает ряды их драйверов на ресурсе `series` |

Одновременно `ids` и `quantity` не передаются. `entry` — объект с полем `id` и параметрами таблицы источника; повтор уже известного идентификатора запрещён. Дополнительные источники читаются поверх [встроенного перечня](<../../src/mst/data/sources.toml>), но не перезаписывают его.

Ответ `get` различает месяц значения `month`, само `value`, день публикации `published` и пометку приблизительной даты `approximate`. История сохраняет пересмотры, поэтому `as_of` восстанавливает известный на день срез, а не просто обрезает месяцы ряда. Загрузка некоторых источников требует доступа к сети и настроенные учётные данные; для FRED требуется переменная `FRED_API_KEY`.

## `corpus`: документы и фрагменты

Параметр `corpus` во всех действиях выбирает набор документов: `"scenario"` по умолчанию или `"model"` для корпуса моделей. У корпусов отдельные манифесты и индексы. Поиск и чтение фрагмента работают локально; загрузка `fetch` обращается к источникам.

| `action` | Параметры | Результат |
|---|---|---|
| `search` | `query`, `as_of`; необязательные `kind`, `region`, `factors`, `k` | Ранжированные фрагменты, опубликованные не позже даты; `k=8` по умолчанию |
| `get` | `id`, `as_of` | Один фрагмент по идентификатору, возвращённому поиском |
| `list` | Нет дополнительных | Манифест, источники, эпизоды и состояние файлов |
| `add` | `key`, `file`, `url` | Регистрирует файл, загруженный вручную, под ключом манифеста и сохраняет происхождение |
| `index` | Нет дополнительных | Запускает индексирование на ресурсе `corpus` |
| `fetch` | Необязательные `ids` | Загружает документы по ключам манифеста; без списка — недостающие документы |

`kind` ограничивает вид материала: `methodology`, `scenario_set`, `transmission`, `episode`; корпус моделей также допускает `market`, рыночные ожидания. `region` и `factors` ограничивают регион и факторы. Поиск возвращает идентификатор фрагмента, документ, путь заголовков, страницы и текст. Чтение фрагмента, опубликованного после `as_of`, отклоняется с датой публикации.

## `scenario`: сохранить и проверить сценарий

Сценарий содержит описание события `narrative`, ссылки `sources`, вмешательства `interventions`, наблюдения `observations` и утверждение человеком `approved_by`. Версии моделей, горизонт и число путей принадлежат запросу расчёта. Одинаковый сценарий поэтому можно пересчитать на другой паре моделей без изменения его экономических утверждений.

| `action` | Параметры | Результат |
|---|---|---|
| `list` | Нет | Сценарии, описание, число вмешательств и наблюдений, утверждение; ошибочные файлы перечисляются отдельно |
| `get` | `id` | Сохранённая спецификация |
| `save` | `id`, `spec` | Проверяет контракт и сохраняет спецификацию; существующий сценарий с тем же именем перезаписывается |
| `validate` | `id` | Проверяет сценарий на последней готовой совместимой паре моделей, возвращает `ok`, `problems`, `labels`, `warnings` |
| `reverse` | `id`, `portfolio`, `draws`, `seed`, `kappa` либо `level` | Ищет по семейству сценария худшую потерю при ограничении цены либо минимальную цену для заданной потери |
| `bench` | `event` | Читает событие набора проверок и начинает журнал обращений к корпусу |
| `bench_save` | `event`, `spec`, необязательный `notes` | Проверяет и сохраняет учебный сценарий вместе с журналом и пустой экспертной рецензией |

`id` допускает строчные буквы, цифры и дефис. Человек утверждает сценарий до расчёта; инструмент сохранения не даёт агенту права заполнять имя человека. `save` проверяет форму, а `validate` — совместимость с доступными моделями и источниками. Параметров выбора версий у MCP-действия `validate` нет: явные версии задаются в запросе `run start`.

Числа вмешательств и наблюдений используют шкалу `level`, `change` или `percent` и календарные месяцы `YYYY-MM`. Процентное изменение допустимо для величины в логарифмической шкале `log100`. Пара «величина — месяц» не может повторяться во вмешательствах. Случайные значения `uniform` и `with_probability` разыгрываются один раз на группу путей, а не заново для каждой позиции.

Проверка называет неизвестную величину, недопустимый месяц, несовместимые единицы, отсутствующее исходное значение, неподдерживаемое смешанное наблюдение, чужую макроверсию сателлитов или отсутствие утверждения. При наличии индекса проверяется видимость фрагментов корпуса на дату модели. `labels` считает метки `event`, ссылки на корпус и `assumption`, а `warnings` раскрывает отсутствие источников, опору только на предположения и пустой сценарий без события.

В обратной задаче `kappa` — верхняя граница цены наблюдений, а `level` — требуемая потеря портфеля; передавайте один режим поиска. `draws` и `seed` задают число розыгрышей и воспроизводимость каждой точки. Ответ содержит найденную точку и исследованные точки с пометкой `estimated`. Точка с ошибкой цены выше десятой части цены не принимается как надёжное основание поиска.

Действия `bench` и `bench_save` предназначены для разработки на наборе событий из репозитория, а не для пользовательского расчёта. Учебный сценарий не утверждается и не вычисляется. В установленном пакете без файлов набора событий действия недоступны по смыслу: используйте обычные `save` и `validate` для рабочего сценария.

## `run`: запросить расчёт и прочитать результат

| `action` | Параметры | Результат |
|---|---|---|
| `start` | Параметры запроса из таблицы | Сохраняет запрос, запускает задачу на ресурсе `runs`, возвращает `run` и `job` |
| `status` | `id` расчёта | Метаданные расчёта и состояние связанной задачи |
| `result` | `id` расчёта | Метаданные, результаты позиций, прогноз целевых показателей и отчёт, если рассчитан портфель |
| `list` | Нет | Сохранённые расчёты, новые первыми |

Для `start` обязательны `scenario`, `draws`, `seed` и один способ задания позиций. Пустой список целевых показателей отличается от отсутствующего параметра и отклоняется.

| Параметр `start` | Смысл и значение по умолчанию |
|---|---|
| `scenario` | Идентификатор утверждённого сценария |
| `portfolio` | Сохранённый портфель; вместо `positions` |
| `positions` | Массив спецификаций позиций прямо в запросе; вместо `portfolio` |
| `base_currency` | Базовая валюта для прямого списка позиций, только `RUB`; портфель несёт собственную базовую валюту |
| `draws` | Число сохраняемых групп розыгрышей параметров и вмешательств |
| `inner` | Путей внутри группы, по умолчанию 1; итоговое число путей равно `draws * inner` |
| `seed` | Начальное состояние генератора случайных чисел |
| `horizon` | Горизонт в месяцах, по умолчанию 12; не короче последнего месяца сценария |
| `macro` | Хеш макроверсии; без параметра выбирается последняя готовая |
| `satellites` | Хеш совместимого сателлитного бандла; без параметра — последний для выбранной макроверсии |
| `targets` | Идентификаторы драйверов для прогноза; без параметра — все построенные драйверы |
| `contributions` | Оценить вклад каждого элемента сценария: повторить расчёт без вмешательства или наблюдения на общих случайных числах; по умолчанию `false` |

Прогноз содержит помесячные квантили 5, 50 и 95 процентов каждого целевого драйвера в его единицах. Отчёт портфеля содержит такие же квантили потерь и `ES95`, среднюю потерю в худших пяти процентах путей. Показатели рассчитываются к концу горизонта, по месяцам и для потери на всём пути. Отчёт также раскрывает покрытие стоимости, исключённые позиции, нарушения допуска и сравнение с пустым сценарием на общих случайных числах.

Блок `interventions` перечисляет величину, месяц, `set` или `shift`, долю активных групп и удалённость установленного значения от базового распределения (`alpha`). Метаданные называют форму макромодели и формы сателлитов. Цена `dist`, когда измерена, характеризует наблюдения и содержит ошибку оценки; односторонняя цена убирает влияние ширины наблюдаемого диапазона в поддерживаемых случаях.

Без наблюдений математическая цена равна нулю, но реализация не создаёт отдельную оценку `Dist`: поле `dist` имеет значение `null` при сериализации `None`. Поэтому клиент не должен ожидать численный ноль. При наблюдениях `null` также может означать отсутствие поддерживаемой оценки; смысл различается по содержанию сценария. Алгоритм находится в [построении путей и цены](<../../src/mst/scenario/build.py>).

## `portfolio`: позиции и их обслуживаемость

Портфель хранит базовую валюту и позиции. Позиция называет тип актива, валюту, номинал в миллионах валюты позиции, коды объекта и собственные условия модели `terms`. Для расчётов поддерживается рублёвая базовая валюта; пересчёт валюты позиции требует соответствующий путь курса.

| `action` | Параметры | Результат |
|---|---|---|
| `list` | Нет | Портфели с валютой и числом позиций; ошибочные файлы перечисляются отдельно |
| `get` | `id` | Сохранённая спецификация |
| `save` | `id`, `spec` | Проверяет контракт и сохраняет портфель, перезаписывая прежний с тем же именем |
| `delete` | `id` | Удаляет портфель; отсутствие файла считается ошибкой |
| `check` | `id`, `scenario` | Проверяет сценарий и входы каждой позиции на выбранных им готовых версиях |
| `exposure` | `id`, `scenario` | Возвращает номинал, курс и исходную стоимость каждой позиции в базовой валюте |

`check` сообщает неизвестный тип позиции, ошибочные `terms`, отсутствие курса, макропеременной или драйвера и причину отказа исторической проверки сателлита. При вмешательстве в макропеременную ответ также показывает, какие драйверы позиций читают переменную и насколько реагируют: нагрузка по модулю ниже 0,1 помечается `barely reacts`. Отсутствие проблемы контракта не доказывает экономическую реалистичность реакции; нагрузку следует сопоставить с содержанием события.

## `model`: каталог и версии моделей

Параметр `kind` разделяет каталог реализаций, макроверсии, сателлитные версии и ответы модели. Не все модели спрашивают агента: набор входов объявляет сама реализация на конкретную дату.

| `kind` | `action` | Параметры | Результат |
|---|---|---|---|
| `catalog` | `list` | Нет | Установленные модели всех видов и назначения величин |
| `macro` | `list` | Нет | Готовые макроверсии, новые первыми |
| `macro` | `describe` | Необязательные `version`, `model_id` | Метаданные названной версии; без хеша — последняя, с фильтром модели, если задан |
| `macro` | `base` | `version`; необязательные `horizon`, `only` | Помесячные `p5`, `p50`, `p95` макропеременных в шкале модели; без задачи и драйверов |
| `macro` | `estimate` | `as_of`, `model_id`; необязательный `form` | Запускает оценку макроверсии на ресурсе `models` |
| `macro` | `backtest` | `as_of`, `model_id`; необязательный `only` | Запускает историческую проверку на ресурсе `models` |
| `satellites` | `list` | Нет | Готовые сателлитные бандлы |
| `satellites` | `describe` | `version` сателлитов | Драйверы и причины отказа обслуживания |
| `satellites` | `estimate` | `version` макромодели; необязательный `assignment` | Оценивает части величин и собирает бандл на ресурсе `models` |
| `inputs` | `list` | `as_of`, необязательный `model_id` | Ключи входов, запись, хеш и время; без модели может перечислить все спрашивающие модели |
| `inputs` | `question` | `as_of`, `model_id`, `key` | Полный текст вопроса и схема ответа |
| `inputs` | `write` | `as_of`, `model_id`, `key`, `payload` | Проверяет и публикует полный ответ; отказ называет поле |
| `inputs` | `status` | `as_of`, `model_id` | Записанные и отсутствующие ключи |

В оценке и исторической проверке `model_id` можно опустить, только если выбор однозначен. Для опроса без `model_id` нужен единственный объявляющий входы плагин, кроме обзорного `list`. `form` принимает `default` или `recursive`; отсутствие сохраняет выбор самой модели. `horizon` у `base` по умолчанию равен 12. В действии `base` список `only` выбирает макропеременные, а в `backtest` передаётся как список идентификаторов эпизодов исторической проверки. `assignment` — объект «величина → идентификатор сателлитной модели», который переопределяет объявленное назначение.

Историческая проверка возвращает качество прогнозов на эпизодах, покрытие интервалов, допуск и сравнение с эталонами. CRPS, непрерывная ранговая вероятностная оценка, измеряет ошибку всего прогнозного распределения; меньшая оценка предпочтительнее. Наличие готовой версии не означает прохождение такой проверки.

## `elicit`: ответить на малый вопрос модели

Для обычного опроса используют `next` и `answer`, сохраняя выданный сервером билет `ticket`. Билет адресует модель, дату, ключ и шаг; его копируют из `answer_call` без редактирования. Ответ `payload` передаётся объектом, а не строкой JSON.

| `action` | Параметры | Результат |
|---|---|---|
| `next` | `as_of`, `model_id`; необязательные `key`, `agent` | Первый недостающий малый вопрос, схема, сохранённый контекст и `answer_call` |
| `answer` | `ticket`, `payload`; необязательный `agent` | Проверяет и сохраняет часть, затем возвращает следующий вопрос либо `complete=true` |
| `list` | `as_of`, необязательный `model_id` | Состояние завершённых входов |
| `status` | `as_of`, `model_id` | Сводка записанных и недостающих входов |

Сочетание `key` и `agent` закрепляет пошаговый опрос за одним объявленным входом. Без имени агента `key` задаёт первый вход, после которого опрос может перейти к остальным. `agent` называет автора в журнале и владении ключом; при совместной работе имя должно совпадать с владельцем. Если спрашивающих моделей несколько, `next` требует `model_id`. Сохранённые части переживают перезапуск, но не считаются завершённым входом, пока собранный ответ не пройдёт полную проверку модели.

Ответы — количественные суждения агента по вопросу и доступным источникам; человек не утверждает их вместо модели. Когда все ключи завершены, оценка запускается отдельно через `model(kind="macro", action="estimate", ...)`. Полноразмерные `question` и `write` доступны через `model(kind="inputs")`; они не нужны для пошагового опроса.

## `interview`: распределить и проверить работу над опросом

Все действия требуют `as_of` и `model_id`. Инструмент управляет состоянием опроса, но не записывает численные ответы: для чисел используется `elicit`.

| `action` | Дополнительные параметры | Результат |
|---|---|---|
| `progress` | Нет | Все ключи, владельцы, завершённые части и публикация |
| `claim` | `key`, `agent`; необязательный `minutes` | Закрепляет ключ за агентом; активное владение другого агента отклоняет второго автора |
| `release` | `key`, `agent` | Освобождает владение вызывающего агента |
| `restart` | `key`, `agent`; необязательный `minutes` | Продлевает владение и возвращает первый недостающий шаг после остановки агента |
| `audit` | Необязательный `key` | Рекомендательные замечания одного ответа либо всех опубликованных ответов |
| `accept` | `key`, `agent`, `reason` | Записывает, почему замечания просмотрены и ответ принят |
| `reopen` | `key`, `steps`, `agent`, `reason` | Сохраняет старую версию и открывает названные шаги для повторного ответа |
| `history` | `key` | Версии ответа |
| `journal` | Необязательные `key`, `limit` | Последние события опроса, при необходимости одного ключа |

Срок владения `minutes` по умолчанию равен 45 минутам, а `limit` журнала — 50 событиям. `steps` содержит идентификаторы шагов из вопроса; неизвестный шаг отклоняется. Замечание аудита само по себе не запрещает публикацию: ведущий агент либо принимает ответ с основанием `reason`, либо возвращает конкретные шаги на исправление. Повторно открытый ключ снова считается недостающим до завершения проверки.

## Команды терминала

Команды вызывают те же сервисы, что инструменты, и нужны для разработки и воспроизводимой диагностики. Примеры выполняются из корня репозитория с установленным `mst`; `MODEL_ID`, `SHA256`, `ID`, `DIR` и `FILE` — заменяемые значения. Оценка выполняется через `python -m`, чтобы входной модуль настроил вычислительное окружение до импорта численных библиотек.

```powershell
# Ряды и драйверы
python -m mst.data update [SERIES ...] --workspace DIR
python -m mst.drivers update [QUANTITY ...] --store DIR --drivers FILE

# Оценка и диагностика
python -m mst.models catalog
python -m mst.models estimate-macro MODEL_ID --as-of 2026-10-29 --store DIR --models DIR
# Дополнительно: --inputs DIR --form default или --form recursive
python -m mst.models estimate-satellites --macro SHA256 --store DIR --models DIR --drivers FILE
# Дополнительно и повторяемо: --model QUANTITY=MODEL_ID
python -m mst.models diagnose --version SHA256 --models DIR
python -m mst.models diagnose-satellites SHA256 --models DIR

# Историческая проверка
python -m mst.metrics backtest MODEL_ID --as-of 2026-10-29 --store DIR --models DIR --episodes bench/model-backtest/episodes.toml

# Сервер и корпус
python -m mst.mcp --workspace DIR
python -m mst.corpus index --corpus DIR
python -m mst.corpus search QUERY --as-of DAY --corpus DIR

# Исполнение уже сохранённого запроса и работа со сценариями
python -m mst.runs ID --workspace DIR
python -m mst.scenario migrate DIR --workspace DIR
python -m mst.scenario reverse ID --workspace DIR --portfolio ID --draws N --seed S --kappa K
# Для минимальной цены вместо --kappa K: --level L
```

`--store` у моделей означает каталог рядов, `--models` — каталог версий, `--drivers` — файл каталога драйверов. Параметр `--corpus` у команды корпуса означает корень корпуса. Квадратные скобки в примерах обозначают необязательные аргументы; скобки не вводятся в PowerShell.

### Дополнительные параметры исторической проверки

| Параметр | Назначение |
|---|---|
| `--only ID ...` | Проверить только названные эпизоды |
| `--satellites --drivers FILE` | Проверить и следующие уровни |
| `--details FILE` | Сохранить полный отчёт |
| `--against REPORT.json` | Сравнить с прежним отчётом на общих ячейках проверочной части плана по правилу двух стандартных ошибок |
| `--target-level LEVEL` | Выбрать уровень сравнения, по умолчанию `macro` |
| `--portfolio ID` | Добавить проверку хвоста потерь портфеля; требует `--satellites` |
| `--mc-bootstrap` | Оценить численную ошибку отдельно от неопределённости по эпизодам |
| `--inputs DIR` | Читать ответы модели на даты эпизодов |
| `--no-rolling` | Не включать проверку безусловного прогноза на сетке дат из плана |
| `--save` | Сохранить отчёт и таблицы рядом с планом, заменив прежний результат модели |

Историческая проверка показывает нормированный CRPS рядом со случайным блужданием, базовым расчётом без события и наивным прогнозом. Отчёт разделяет уровни и горизонты, показывает покрытие интервалов, их ширину, допуск и части плана для настройки и проверки. Параметр `--portfolio` добавляет проверку средней хвостовой потери по методу Acerbi–Székely с интервалами и перечнем выпавших эпизодов; `--mc-bootstrap` отделяет численную ошибку от разброса между эпизодами.

Историческая проверка сохраняет версии эпизодов в отдельном каталоге `backtest`, поэтому рабочий расчёт не выбирает их как последние пользовательские версии. Код выхода 1 означает непроверенный эпизод или нарушение условия допуска; завершение процесса само по себе не означает пригодность модели. Состав отчёта и правила сравнения следует читать вместе с [метриками платформы](<../../src/mst/metrics/README.md>).

Команда `migrate` переносит старые сценарии только тогда, когда перевод сохраняет числа. Неоднозначные прежние причины перечисляются для переклассификации человеком или агентом; отказ на одном непереводимом файле не должен молча менять остальные. Перенос не заменяет проверки экономического смысла сценария по [руководству пользователя](<../howto/first-session.md>).
