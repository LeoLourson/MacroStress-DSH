# Документация MacroStress

[English](<README.en.md>)

MacroStress рассчитывает распределение целевых показателей при заданном событии.
Выберите путь чтения по задаче: пользователю нужен порядок подготовки расчёта,
математику — определения и границы метода, разработчику — устройство и контракты.
Начинать с математического описания для установки программы не требуется.

![Событие превращается в сценарий, человек утверждает условия, модели рассчитывают последствия](<images/event-to-result.ru.svg>)

На схеме человек задаёт событие и проверяет подготовленный сценарий. Агент ищет
источники для чисел, но последствия считает с помощью экономических моделей,
поскольку текст события сам по себе не задаёт будущий ход всех величин.

## Пользователю: получить и прочитать расчёт

Если MacroStress ещё не подключён к приложению с агентом, начните с подключения.
Если инструменты уже доступны, переходите к первому сеансу: инструкция объясняет,
что подготовить заранее и какие ответы проверить до расчёта.

| Задача | Руководство | Что должно получиться |
|---|---|---|
| Подключить сервер к приложению с агентом | [Подключение через MCP](<howto/mcp.md>) | Приложение вызывает инструменты сервера и видит нужный каталог данных |
| Установить интеграцию DeepSeek Harness | [Установка в DeepSeek Harness](<howto/install.md>) | Сервер и раздел состояния используют один каталог данных |
| Подготовить первый расчёт | [Первый сеанс](<howto/first-session.md>) | Проверены данные, версии моделей, сценарий, портфель и результат |
| Найти действие и его параметры | [Справочник инструментов](<reference/tools.md>) | Понятно, что читает, меняет и возвращает вызов |
| Подготовить источники для сценариев | [Корпус сценариев](<../corpus/README.md>) | Источники доступны поиску с датами публикации и проверяемыми ссылками |

## Математику: понять, какой закон вычисляется

[Общая схема стресс-тестирования](<concept/formalization.md>) определяет уровни моделей,
вмешательства, наблюдения и условный прогноз. Вмешательство меняет правило порождения
величины, а наблюдение ограничивает распределение исходов после вмешательства.
Там же дано определение цены сценария и разобраны условия существования решения.

Для конкретного метода расчёта переходите от общей схемы к описанию плагина.
Плагин — отдельное расширение с собственной математической моделью; смена плагина
не меняет смысл файла сценария, но может изменить рассчитанные последствия.

| Как устроена векторная авторегрессия | [Модель bvar](<../src/mst/plugins/bvar/README.md>) и [математический справочник](<../src/mst/plugins/bvar/REFERENCE.md>) |

| Как проверяется качество распределения | [Проверка моделей на истории](<../src/mst/metrics/README.md>) |

## Как устроен комплект

Документы разложены по функции: если нужно понять метод, читайте `concept`;
если нужно выполнить действие, читайте `howto`. Поля и статусы ищите в `reference`,
а причины выбора устройства системы — в `adr`.
Один документ хранит одно правило; маршруты читателей ссылаются на общие документы,
поэтому математическое определение не нужно копировать в каждую инструкцию.
Описание пакета остаётся рядом с пакетом, а описание проверок — рядом с проверками.

Русский текст служит исходным для английского перевода. Рисунки входят в комплект
вместе с подписями и текстовыми объяснениями; учебная иллюстрация не выдаётся
за результат расчёта. Правила поддержки комплекта собраны в
[справочнике документации](<reference/documentation.md>).
