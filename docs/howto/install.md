# Установка интеграции DeepSeek Harness

[English](<install.en.md>)

Интеграция MacroStress подключает расчётный сервер к DeepSeek Harness и добавляет
агенту рабочие руководства и краткое состояние данных. Сначала выберите, что должен
запускать сервер: опубликованный Python-пакет или вашу локальную копию репозитория.
Пакет проще установить, а локальная копия нужна, если вы меняете код или используете
возможности, которые ещё не вошли в выпуск.

DeepSeek Harness — приложение, в котором пользователь общается с агентом. MacroStress
работает отдельным процессом; связь идёт через MCP (Model Context Protocol), протокол
вызова инструментов. Расчёты выполняет Python-пакет `mst`, а
[пакет интеграции](<../../dsh/README.md>) связывает сервер с приложением.
Для другого приложения используйте [общее руководство подключения](<mcp.md>).

Сервер читает ряды, сценарии и результаты из рабочего каталога. Плагин показывает
агенту состояние того же каталога; если пути разойдутся, агент увидит сведения
не о тех данных, с которыми работают инструменты.

## Выбрать Python-часть

Нужны Python 3.12 или новее и [uv](https://docs.astral.sh/uv/) — программа для установки
Python-пакетов. Требования пакета фиксирует [манифест Python-проекта](<../../pyproject.toml>).
Установка интеграции не загружает экономическую историю и корпус источников.

Вариант с опубликованным пакетом не требует клонировать Python-репозиторий ради сервера.
[Конфигурация бандла](<../../dsh/cordis.patch.yml>) запускает команду:

```powershell
uvx --from 'macrostress>=1.1.0' macrostress
```

`uvx` подготавливает среду пакета и запускает сервер. Нижняя граница версии
не обещает, что выпуск содержит все возможности ветки main: для работы
с изменениями из main выберите локальную копию.

Для локальной разработки выполните команды из каталога, где должен лежать проект:

```powershell
git clone https://github.com/LeoLourson/MacroStress-DSH
cd MacroStress-DSH
uv sync
uv run python -m mst.mcp --help
```

`uv sync` создаёт виртуальную среду `.venv` и устанавливает зависимости из
[зафиксированного списка](<../../uv.lock>). Последняя команда печатает справку
и завершает процесс; она проверяет импорт сервера, но не подключение к приложению.
Для работы сервер запускается без `--help` и остаётся ждать MCP-клиента.

## Подключить бандл к профилю

Бандл — устанавливаемый пакет, который добавляет в профиль приложения сервер
и плагин состояния. Профиль хранит настройки приложения и выбранных расширений.
В DeepSeek Harness откройте Plugins → Add plugin и выберите каталог `dsh`
в клоне репозитория; назначение каталога описывает [README интеграции](<../../dsh/README.md>).
Выполните действия, которые менеджер плагинов покажет после установки.

Если агент управляет плагинами через инструмент `plugin_manager`, установка локального
бандла выполняется действием `install_bundle` с абсолютным путём к каталогу `dsh`.
Разрешение на установку и запуск предлагаемых сборочных сценариев принимает пользователь.
Ручное создание ссылок в `node_modules` не заменяет установку менеджером плагинов.

Названия действий приведены для DeepSeek Harness 0.2.2-rc.3. Установочный интерфейс
другой версии сверяйте с документацией приложения; способ установки бандла
не меняет протокол сервера MacroStress.

## Выбрать рабочий каталог

При обычной установке сервер и плагин ищут каталог по одному правилу:

1. Путь из переменной `MACROSTRESS_WORKSPACE`, если переменная задана.
2. Первый существующий каталог: `~/.macrostress/workspace`, каталог данных пользователя
   операционной системы, затем `./workspace` относительно каталога запуска.
3. Если подходящего каталога нет, сервер создаёт каталог данных пользователя;
   при невозможности создать его использует `./workspace`.

Каталог данных пользователя — `%LOCALAPPDATA%/macrostress/workspace` в Windows,
`~/Library/Application Support/macrostress/workspace` в macOS и
`$XDG_DATA_HOME/macrostress/workspace` в Linux; без `XDG_DATA_HOME` используется
`~/.local/share/macrostress/workspace`.
Проверить фактический путь можно вызовом `jobs(action="state")`.

Для явного выбора каталога или локального Python-процесса переопределяются обе записи
бандла в настройках профиля. Патч профиля — YAML-файл, который приложение применяет
после конфигурации бандла. Пример для Windows использует условные абсолютные пути;
перед сохранением замените их своими.

```yaml
- id: mcp-macrostress
  config:
    serverName: macrostress
    transport: stdio
    command: 'C:/src/MacroStress-DSH/.venv/Scripts/python.exe'
    args: ['-u', '-m', 'mst.mcp', '--workspace', 'C:/data/macrostress']
    env:
      PYTHONUTF8: '1'
    failOnStartupError: false
- id: dsh-macrostress
  config:
    workspace: 'C:/data/macrostress'
```

Путь команды для macOS и Linux заканчивается на `.venv/bin/python`.
Переопределение `config` заменяет блок целиком, поэтому сохраняйте транспорт,
имя сервера, аргументы и необходимые переменные. Настройки машины и секреты
не должны попадать в общий репозиторий.

## Передать ключ источника

Глобальные ряды, загружаемые из FRED, требуют ключа `FRED_API_KEY`.
Получить ключ можно по [инструкции FRED](https://fred.stlouisfed.org/docs/api/api_key.html).
Другие источники могут иметь собственные ограничения; список задаёт
[реестр источников](<../../src/mst/data/sources.toml>).

DeepSeek Harness очищает окружение дочерних процессов от секретов, поэтому наличие
ключа в системном окружении не доказывает, что сервер его получил.
Передайте существующий секрет через поддерживаемый приложением механизм учётных данных
или задайте переменную в `env` серверной записи профиля. Не отправляйте значение ключа
в чат и не вставляйте его в публичный пример. Задачи загрузки наследуют окружение сервера.

## Проверить установку

В новом сеансе попросите агента вызвать `jobs(action="state")` и `guide()`.
Первый ответ должен показать выбранный каталог; второй — доступные руководства.
Проверьте также карточку MacroStress в Plugins и раздел состояния у агента.
Отсутствие версий моделей до первой оценки нормально, но неверный путь каталога
нужно исправить до загрузки данных.

Проверка интеграционного кода без работающего приложения:

```powershell
node dsh/test/smoke.mjs
```

Команда из корня репозитория проверяет регистрацию руководств, раздел состояния,
повторное чтение изменённого снимка и снятие регистрации. Проверка не доказывает,
что приложение установило бандл или что внешний источник доступен.
После подключения переходите к [первому расчёту](<first-session.md>).

Если инструментов нет, запустите команду серверной записи вручную со справкой `--help`:
так видны неверный путь и ошибка импорта. Если загрузка не удалась, прочитайте
`jobs(action="log", id=...)`; занятый ресурс освобождается после завершения
или осознанной отмены задачи. При ошибке сертификата не отключайте проверку TLS:
диагностика источников описана в [справочнике инструментов](<../reference/tools.md>).
