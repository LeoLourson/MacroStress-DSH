# Как добавить модель плагином

Плагин MacroStress — Python-пакет, который объявляет модели и их совместимость с платформой. Пакет может рассчитывать позиции, строить макроэкономические пути или переводить пути предыдущих уровней в показатели объектов. Для новой модели создайте пакет нужного вида, проверьте объявление и вычисления, затем подключите пакет к реестру; изменение ядра для выбора конкретной модели не требуется.

Руководство рассчитано на разработчика Python. Термин «SDK» означает набор интерфейсов и помощников для автора расширения: SDK позиций задаёт расчёт стоимости, а SDK моделей — оценку и построение путей. Точные структуры собраны в [контрактах платформы](<../reference/platform.md>), математический смысл уровней — в [общей схеме](<../concept/formalization.md>).

## Выбрать вид модели и создать пакет

| Что должна делать модель | Поле объявления `Plugin` | Базовый класс |
|---|---|---|
| Рассчитать стоимость позиции на готовых путях | `models` | `CalculationModel` из `mst.plugin_sdk` |
| Построить совместные макропоказатели уровня 0 | `macro` | `MacroModel` из `mst.model_sdk` |
| Построить показатели объектов следующего уровня | `satellites` | `SatelliteModel` из `mst.model_sdk` |

Один пакет может объявить модели нескольких видов. Создание через команду выбирает исходный шаблон, а не запрещает дальнейшее расширение пакета. Встроенные модели подключены тем же способом; установленный состав показывает `model(kind="catalog", action="list")`.

Команды выполняются из корня репозитория в окружении с установленным `mst`. Имена `gold`, `walk` и `link` — примеры новых пакетов; команда `new` откажется перезаписывать существующий каталог.

```powershell
python -m mst.plugin new gold --kind position --label "Золото"
python -m mst.plugin new walk --kind macro --label "Блуждание"
python -m mst.plugin new link --kind satellite --quantity share_price
python -m mst.plugin check gold
python -m mst.plugin demo-run gold
python -m mst.plugin check
```

Генератор создаёт объявление, модель, тест и описание пакета. Шаблон позиции дополнительно содержит демонстрационный пример, который проверяется без сети и оценённых версий. Генератор и его аргументы определены в [команде `mst.plugin`](<../../src/mst/plugin.py>): `--kind` выбирает вид, `--type-id` задаёт тип позиции, `--quantity` — величину сателлита, `--label` — подпись, `--dest` — родительский каталог вне дерева встроенных плагинов.

```text
src/mst/plugins/<plugin_id>/
  __init__.py               экспорт модели и объявления plugin
  plugin.py                 plugin = Plugin(...)
  model.py                  реализация модели
  tests/test_<plugin_id>.py  проверка пакета
  README.md                 назначение и ограничения модели
```

## Подключить пакет без правки ядра

Платформа собирает один реестр из пакетов пространства имён `mst.plugins`, установленных точек входа группы `mst.plugins` и каталогов переменной `MST_PLUGINS_PATH`. Выбор способа зависит от распространения пакета:

| Способ | Когда использовать | Цена выбора |
|---|---|---|
| Пакет `mst.plugins.<id>` в исходном дереве | Модель поставляется вместе с MacroStress | Изменения модели связаны с выпуском репозитория |
| Точка входа Python-распределения | Модель устанавливается и выпускается отдельно | Нужно упаковать распределение и установить его в окружение сервера |
| `MST_PLUGINS_PATH` | Локальная разработка без установки распределения | Путь окружения нужно согласовать у проверки и сервера |

Значения `MST_PLUGINS_PATH` разделяются системным разделителем: `;` в Windows и `:` в POSIX. Несуществующий каталог считается ошибкой загрузки с именем пути. Сам механизм обнаружения реализован в [реестре плагинов](<../../src/mst/plugins/__init__.py>).

Созданный вне репозитория пакет проверяется непосредственно по пути:

```powershell
python -m mst.plugin new gold --dest C:\models
python -m mst.plugin check --path C:\models\gold
python -m mst.plugin demo-run --path C:\models\gold
```

Проверка `--path` сверяет пакет и с уже установленным набором, поэтому обнаруживает конфликт идентификаторов до подключения. При импорте по пути пакет получает синтетическое имя `mst_plugin_<имя_каталога>`. Используйте относительные импорты, например `from .model import MODEL`: абсолютный `import gold.model` не следует из имени папки и может завершиться `ModuleNotFoundError`.

## Объявить возможности и совместимость

Объект `Plugin` сообщает платформе, какие модели предоставляет пакет. Поля принадлежат [контракту объявления](<../../src/mst/plugin_sdk/plugin.py>), а не конкретному виду актива.

```python
from mst.plugin_sdk import Plugin
from .model import MODEL
from .demo import DEMO_CASE

plugin = Plugin(
    plugin_id="gold",
    version="0.1.0",
    sdk=">=1.0,<2.0",
    label="Позиция в золоте",
    description="Стоимость позиции следует готовым путям цены золота.",
    models=(MODEL,),
    demo=(DEMO_CASE,),
)
```

Пример показывает форму объявления; `MODEL` и `DEMO_CASE` должны быть определены в собственном пакете. Для макро- и сателлитных моделей указывают `model_sdk` вместо `sdk`, если в пакете нет моделей позиций.

| Поле | Требование и смысл |
|---|---|
| `plugin_id` | Уникальное имя в форме `lower_snake_case`; задаёт начало идентификаторов моделей и метрик |
| `version` | Версия пакета в форме `x.y.z` |
| `label`, `description` | Читаемое название и назначение |
| `sdk` | Совместимый диапазон SDK позиций; обязателен при непустом `models` |
| `model_sdk` | Совместимый диапазон SDK моделей; обязателен при непустом `macro` или `satellites` |
| `models`, `macro`, `satellites` | Кортежи экземпляров моделей; хотя бы один кортеж должен быть непустым |
| `demo` | Самодостаточные примеры для моделей позиций |
| `guides` | Пути к руководствам модели, которые сервер отдаёт через инструмент `guide` |

Идентификаторы модели и метрики начинаются с `<plugin_id>.`, например `gold.paths.v1`. Один тип позиции может обслуживать только одна модель. Для сателлитов правило другое: несколько моделей могут заявить одну величину, но оценка требует однозначного назначения. Явное назначение `--model ВЕЛИЧИНА=МОДЕЛЬ` выбирает модель и может передать ей даже величину вне её списка `quantities`.

## Реализовать модель позиции

Модель позиции получает уже построенные пути, поэтому её задача — вычислить стоимость без чтения файлов, сети и собственных случайных розыгрышей. [Класс `CalculationModel`](<../../src/mst/plugin_sdk/model.py>) разделяет расчёт на требования, проверку входов и вычисление результата.

```python
class GoldModel(CalculationModel):
    model_id = "gold.paths.v1"
    version = "0.1.0"
    label = "Золото на путях цены"
    instrument_types = ("gold_position",)
    terms_schema = Terms
    metrics = ("gold.value_current", "gold.pnl", "gold.loss")
    required_metrics = metrics

    def requirements(self, position, options):
        # Return DataRequirements before reading paths.
        ...

    def validate(self, prepared):
        # Return diagnostics about prepared inputs.
        ...

    def calculate(self, prepared, context):
        # Return CalculationResult on the shared paths.
        ...
```

Код показывает интерфейс, а не готовую модель. `requirements` возвращает `DataRequirements`: имена макропеременных и требования `DriverRequirement` к величине и объекту. Если объект не задан прямо, платформа ищет его по кодам позиции. Не найденный обязательный драйвер сохраняется как причина отказа, а не заменяется произвольным объектом.

Метод `validate` возвращает диагностику `Diagnostic`. Ошибка с уровнем `error` останавливает позицию со статусом `invalid`; предупреждение не равнозначно отказу. Метод `calculate` получает `PreparedInputs` с разрешёнными входами и `CalculationContext` с общими путями, датой, горизонтом, базовой валютой и `seed`. Результат собирают помощником `envelope`: массив `value_change` содержит изменение стоимости на каждом пути, а обязательные метрики должны присутствовать под объявленными именами.

Собственные условия позиции описывает Pydantic-модель `terms_schema` с `extra="forbid"`, то есть неизвестные поля запрещены. Дюрация, доля потери при дефолте и идентификатор рынка должны быть явно заданы там, где модель требует их от аналитика. Отсутствующее обязательное поле должно приводить к диагностике, а не к незаметной подстановке экономического числа.

### Добавить демонстрационный пример

`DemoCase` связывает позицию, фиксированные пути и карту требований к драйверам. Например, требование величины `gold_price` сопоставляется конкретному драйверу `gold_price:demo`:

```python
from datetime import date
import numpy as np
from mst.plugin_sdk import DemoCase, FixedPaths, Position

paths = FixedPaths(
    drivers={"gold_price:demo": np.array([[100., 102., 104.], [100., 98., 96.]])},
    start=date(2026, 9, 1),
)
case = DemoCase(
    name="demo",
    position=Position(id="demo", type="gold_position", notional=100.),
    paths=paths,
    drivers={"gold_price": "gold_price:demo"},
)
```

Первый столбец содержит исходный месяц, остальные — будущие месяцы; строки представляют разные пути. `FixedPaths` реализует тот же интерфейс чтения, что настоящий расчёт: `draws`, `horizon`, `months`, `variables`, `macro`, `driver`, `flags`. Проверка выполняет пример дважды и сравнивает результаты. Если `completes=True`, пример обязан рассчитаться; `demo-run` печатает квантили 5, 50 и 95 процентов, а для потерь — среднюю потерю в худших пяти процентах (`ES95`).

## Реализовать макромодель

[Контракт `MacroModel`](<../../src/mst/model_sdk/contracts.py>) задаёт основной жизненный цикл:

```text
estimate(MacroEstimateContext) -> MacroEstimate(meta, arrays)
load(meta, arrays)             -> объект сохранённой модели
simulate(model, ScenarioPlan, *, draws, seed) -> MacroSimulation
```

Контекст оценки несёт хранилище рядов `store`, реестр `registry` и дату видимости `as_of`. Для модели с опросом доступны завершённые ответы `inputs`, каталог точек сохранения `checkpoints` и функция `fragment`, проверяющая видимость фрагмента корпуса на дату. Модель строит свою панель только из доступных сведений; платформа публикует возвращённые метаданные и массивы как неизменяемую версию.

Макроверсия обязана содержать `as_of`, `ids`, `months`, `shocks`, а также массивы `panel_y` и `panel_approximate`. Идентификатор оценившей модели платформа хранит в `meta["model"]`; дополнительные массивы читает обратно собственный метод `load`. Шоки и скрытые координаты принадлежат модели: сценарий не выбирает их имена. Атрибут `latents` перечисляет скрытые координаты, например пути режимов или волатильности, которые наблюдения могут перевзвешивать.

План `ScenarioPlan` передаёт горизонт, линейные ограничения `constraints`, реализованные вмешательства `interventions` и число путей в группе `inner`. Аргумент `draws` считает группы; модель возвращает `draws * inner` путей. Пути одной группы сохраняют один розыгрыш параметров и вмешательств, а наблюдения изменяют разрешённые случайные координаты внутри группы.

Для цены наблюдений модель может вернуть `ConstraintLaw` методом `constraint_law`. Закон содержит средние, ковариации, логарифмы весов и номера групп условных гауссовых компонент. Если закон нельзя представить такой смесью, модель может вернуть логарифмы вероятностей ограничений методом `log_box_probability(model, plan, low, high, *, draws, seed)`: одно значение на группу. Возврат `None` из обоих методов означает, что модель цену не измеряет; отсутствие оценки нельзя выдавать за ноль.

Оценка макромодели запускается отдельно:

```powershell
python -m mst.models estimate-macro MODEL_ID --as-of 2026-10-29 --store workspace/series --models workspace/models
```

### Объявить форму исполнения вмешательств

SDK моделей передаёт `Intervention` с полями `target`, `months`, `kind`, `values` и `active`. `kind` принимает `set` или `shift`; `values` имеет одну строку на группу и один столбец на месяц. Маска `active` отличает неактивное вмешательство от активного нулевого значения. Случайное значение вмешательства разыгрывает платформа до вызова модели.

Если `structural_form(model)` возвращает `None`, действует форма `default`. Макромодель решает ограничения с подстановкой вмешательств через `constraints_under_default`, а платформа после симуляции вызывает `apply_default`. Замена ячеек не пересчитывает другие ячейки этого же уровня, включая будущие месяцы; следующие уровни получают уже изменённый путь.

Модель с рекурсивной формой возвращает `StructuralForm(order_within_month, time_recursion)` и сама исполняет вмешательства внутри симуляции и закона ограничений. `order_within_month` задаёт порядок величин внутри месяца, `time_recursion` сообщает о временной зависимости. Формы `default` и `recursive` выбираются при оценке через `--form`, если модель поддерживает выбор; сохранённая форма фиксируется в версии. Реализация формы по умолчанию находится в [помощниках вмешательств](<../../src/mst/model_sdk/interventions.py>).

### Добавить вопросы модели

Модель, оцениваемая по суждениям агента, объявляет ключи через `input_keys(as_of)`, полный вопрос через `question(context, key)` и проверку через `check_input(context, key, payload)`. Для больших ответов можно переопределить `input_steps`, `check_input_step` и `assemble_input`. Сборка объединяет сохранённые части без добавления чисел и проходит полную проверку перед публикацией.

Дополнительный контекст шага возвращает `input_step_context`, обратное разбиение опубликованного ответа — `input_parts`, а рекомендательные замечания — `audit_input`. Общий механизм опроса сохраняет части, владельцев ключей, историю и журнал; предметные вопросы и правила проверки остаются в модели. Агент отвечает через `elicit`, управление проверкой идёт через `interview`, а полноразмерные чтение и запись — через `model(kind="inputs")`. Человек утверждает сценарий, но не ответы модели. Пример объявления руководств и моделей расположен в [плагине `expert`](<../../src/mst/plugins/expert/plugin.py>).

## Реализовать сателлитную модель

Сателлит оценивает назначенные величины и строит их пути на уже построенных уровнях. `SatelliteEstimateContext` несёт реестр объектов, панель макроверсии, дату, хеш макроверсии, назначенные `quantities`, историю предыдущих уровней `upper_history` и точки сохранения. Историю величин готовит [модуль `mst.drivers.history`](<../../src/mst/drivers/history.py>).

```text
estimate(SatelliteEstimateContext) -> SatelliteEstimate(parts, residuals)
load(parts) -> объект модели назначенных величин
simulate(model, upper, drivers, interventions, *, correlation, shocks, seed, stream)
    -> DriverPaths
```

Каждая часть `SatellitePart` хранит `months`, `nodes`, `driver`, `rows` и `checks`. Платформа добавляет идентификатор модели и отклоняет часть, приписывающую результат другой модели. Границы обучающей истории `train_low` и `train_high` нужны проверке выхода путей за изученный диапазон. Остатки `residuals` выровнены по месяцам части; из них платформа собирает корреляцию драйверов всего бандла.

`upper` имеет тип `UpperPaths`: макросимуляция и пути предыдущих уровней после вмешательств. Уровень величины задаёт реестр; уровни рассчитываются по возрастанию. Сателлит уровня 1 читает макропути, а модель уровня 2 может читать и макропути, и драйверы уровня 1. Учебная модель второго уровня описана в [пакете `reflevel2`](<../../src/mst/plugins/reflevel2/README.md>).

Сателлит применяет вмешательства своих величин ровно один раз до возврата путей. Для формы `default` используются `inner_of_groups` и `apply_default`; рекурсивная форма исполняет вмешательства внутри собственных уравнений. Следующий уровень должен получить результат уже после вмешательств.

### Использовать совместные случайные остатки

Платформа разыгрывает совместный нормальный вектор по полной матрице корреляций уровня, затем передаёт каждой модели её срез `shocks`. Для группы случайного пути и уровня используется поток `default_rng([seed, 0, level, repetition])`; потоки разных уровней независимы. Столбцы соответствуют порядку `drivers`, но включают только драйверы с собственной историей. Драйверы с пометкой `parameters_from_above`, чьи параметры перенесены от узла выше, остаются на независимом шуме модели.

Массив `shocks` имеет размер «пути × шаги × коррелируемые драйверы модели». Число шагов равно горизонту плюс наибольшая длина истории части минус один; модель читает первые необходимые ей строки. Аргумент `stream` разделяет дополнительные случайные потоки моделей одного бандла. Игнорировать `shocks` нельзя: тогда измеренная межмодельная корреляция не попадёт в совместные пути.

Назначение величин при оценке записывается явно, если выбор неоднозначен:

```powershell
python -m mst.models estimate-satellites --macro SHA256 --store workspace/series --models workspace/models --drivers workspace/drivers/catalog.json --model share_price=MODEL_ID
```

## Проверить пакет и сохранить границы

`python -m mst.plugin check` проверяет совместимость диапазонов SDK, версии, имена, объявления моделей, уникальность типов позиции и схемы входов. Для позиции проверяются демонстрационные пути, соответствие требований, обязательные метрики и совпадение повторных вычислений. Макро- и сателлитному пакету без моделей позиций демонстрационный пример не нужен, но проверка объявления не заменяет тесты его оценивания и симуляции.

Проверка `mst.model_sdk.testing.check_shocks` вызывает сателлит с разными `shocks` при одном `seed`. Находка возникает, если модель не принимает аргумент, меняет форму путей или возвращает одинаковые пути. Пакет должен отдельно проверить форму выходных массивов, применение вмешательств и собственные экономические ограничения. Общие проверки находятся в [проверках совместимости](<../../tests/plugins/test_conformance.py>) и [проверках границы диспетчера](<../../tests/plugins/test_boundary.py>).

Разрешённые зависимости модели — её собственный пакет, SDK, контракты и помощники подготовки истории и реестров. Управление расчётом (`mst.engine`, `mst.runs`, `mst.portfolio`, `mst.metrics`, `mst.models`, сборка сценария и реестр плагинов) не должно импортироваться внутрь модели. Модель также не должна читать реализацию другого плагина как скрытый общий сервис.

Если нужного поля путей, результата или контекста нет в SDK, сначала согласуют расширение контракта и его совместимость. Обход через импорт управления расчётом привязал бы плагин к внутреннему устройству ядра; отдельное расширение SDK дороже при разработке, зато оставляет модель независимо подключаемым пакетом.
