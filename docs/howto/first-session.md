# Первый расчёт через агента

[English](<first-session.en.md>)

Для первого расчёта нужны история величин, версии экономических моделей, сценарий
и объект оценки. Попросите агента проверить готовность рабочего каталога, а затем
подготовить недостающее. Сценарий сначала утверждает человек; поручение выполнить
расчёт даётся отдельно. Само сохранение сценария не разрешает запуск расчёта.

Инструкция предполагает, что приложение уже подключило сервер MacroStress.
Если инструментов ещё нет, начните с [подключения через MCP](<mcp.md>).
MCP, или Model Context Protocol, — протокол, по которому приложение с агентом
вызывает инструменты сервера. Вызовы в блоках ниже адресованы агенту: это не команды
терминала и не Python-программа.

![Разделение подготовки сценария, утверждения человеком и численного расчёта](<../images/event-to-result.ru.svg>)

Агент формализует условия события по источникам, а модели рассчитывают последствия.
Версии моделей готовятся заранее и могут использоваться в нескольких расчётах.
Если данные или версии уже есть, повторять подготовку без причины не нужно.

## Проверить исходное состояние

Начните с просьбы: «Покажи, какие данные и модели уже готовы, и что нужно для первого
расчёта на выбранную дату». Дата расчёта — последний день, сведения на который
разрешено использовать; месяц последнего наблюдения может быть раньше этой даты.

```text
jobs(action="state")
model(kind="catalog", action="list")
model(kind="macro", action="list")
model(kind="satellites", action="list")
```

Первый вызов возвращает путь рабочего каталога, версии моделей, состояние корпуса
и число сохранённых объектов. Каталог моделей перечисляет установленные плагины,
то есть расширения с математическими методами. Агент должен назвать выбранную модель
по идентификатору `model_id`, поскольку несколько моделей могут быть установлены
одновременно. Не выбирайте модель только потому, что её версия оказалась последней.

Долгая операция возвращает идентификатор задачи `job`, а не готовый результат.
Дождитесь завершения задачи и проверьте её код выхода; при ошибке прочитайте журнал.

```text
jobs(action="wait", id=JOB_ID)
jobs(action="log", id=JOB_ID)
```

`JOB_ID` заменяется идентификатором из ответа. Если `running` ещё равен `true`,
повторите ожидание. Команды отмены нужны только для задачи, которую решено остановить:
отсутствие нового вывода само по себе не доказывает зависание.

## Подготовить историю и версии моделей

Временной ряд хранит значения одной величины по месяцам с датами публикации.
При обновлении агент обращается к внешним источникам; условия источников и ключи
доступа описаны в [руководстве подключения](<mcp.md>).

```text
series(action="update")
model(kind="macro", action="estimate", model_id=MODEL_ID, as_of=CALCULATION_DATE)
```

Здесь и далее имена прописными буквами — места для значений из ответа инструмента
или выбранных условий. `CALCULATION_DATE` имеет вид `YYYY-MM-DD`.
Сначала нужно дождаться загрузки рядов, затем — оценки макромодели. Оценка возвращает
версию с хешем: хеш служит идентификатором неизменяемого набора метаданных и массивов.

Некоторые модели перед оценкой требуют количественного опроса агента. В таком случае
агент читает руководство `model-inputs` и завершает малые вопросы через `elicit`;
пустые ответы и тестовые числа не заменяют опрос. Человек утверждает сценарий,
но не заполняет числа экспертной модели вместо агента.

Сателлитные модели получают общеэкономические траектории и рассчитывают показатели
отраслей, компаний или активов. Загружать нужно те величины, которые потребуются
объекту оценки; список назначений виден в каталоге моделей.

```text
series(action="update", quantity="share_price")
model(kind="satellites", action="estimate", version=MACRO_VERSION)
model(kind="satellites", action="describe", version=SATELLITE_VERSION)
```

`share_price` — пример величины «цена акции», а не универсальная команда для любого
портфеля. `MACRO_VERSION` — хеш выбранной макроверсии; `SATELLITE_VERSION` — хеш
полученного комплекта сателлитных моделей. Проверьте отклонённые драйверы: драйвер —
конкретная величина конкретного объекта, например цена одной акции. Наличие объекта
в каталоге ещё не означает, что его модель прошла проверку.

## Подготовить и утвердить сценарий

Опишите событие словами, например: «Что будет, если центральный банк установит ставку
21 % на год?» Условие учебное, оно не утверждает состоявшегося решения.
Агент должен уточнить календарные месяцы, найти основания для остальных чисел
и показать условия до расчёта.

```text
guide(name="scenario-from-corpus")
corpus(action="search", query=SEARCH_QUERY, as_of=CALCULATION_DATE)
scenario(action="save", id=SCENARIO_ID, spec=SCENARIO_SPEC)
scenario(action="validate", id=SCENARIO_ID)
```

Корпус — собрание документов и описаний прошлых событий. Если индекс ещё не готов,
агент сначала организует загрузку и индексацию по [руководству корпуса](<../../corpus/README.md>).
Число из текста события отмечается как условие события; число из источника получает
ссылку на конкретный фрагмент; самостоятельно выбранное число отмечается допущением.

Проверьте, какие условия агент записал вмешательствами, а какие наблюдениями.
Вмешательство навязывает значение или сдвиг величины, например решение о ставке;
наблюдение ограничивает ожидаемый исход, например снижение выпуска.
Следствия, которых вы не задавали, должны рассчитывать модели. Агент не заполняет
`approved_by` своим именем: поле фиксирует утверждение человеком.

Проверка `validate` показывает технические проблемы и предупреждения, но не заменяет
экономическую оценку сценария. После правок и вашего утверждения агент повторяет
проверку; изменение сценария требует проверить утверждённые условия заново.

## Проверить объект оценки и запустить расчёт

Для портфеля подготовьте валюту и позиции: вид актива, текущую стоимость, коды объекта
и обязательные условия его модели. Поля перечислены в [контрактах платформы](<../reference/platform.md>).
Неизвестное значение не заменяют нулём только ради прохождения проверки.

```text
portfolio(action="save", id=PORTFOLIO_ID, spec=PORTFOLIO_SPEC)
portfolio(action="check", id=PORTFOLIO_ID, scenario=SCENARIO_ID)
```

Проверка сопоставляет позиции с доступными драйверами и моделями и объясняет отказы.
Если сценарное изменение почти не достигает драйвера позиции, агент должен показать
предупреждение до расчёта. Исправить состав моделей или считать неполное покрытие —
разные решения; во втором случае вывод относится только к оценённой части портфеля.

Когда вы поручите выполнить расчёт, агент явно задаёт версии и горизонт в месяцах.
Траектория — один возможный ход величин по месяцам; число траекторий влияет
на точность численного приближения, но не устраняет ошибки модели.

```text
guide(name="run-report")
run(action="start", scenario=SCENARIO_ID, portfolio=PORTFOLIO_ID,
    macro=MACRO_VERSION, satellites=SATELLITE_VERSION,
    horizon=12, draws=2048, seed=42)
```

Параметры `12`, `2048` и `42` приведены для воспроизводимого учебного запроса,
а не как универсальный стандарт точности. Горизонт не должен обрезать последний
месяц условий сценария. Из ответа возьмите идентификаторы задачи и расчёта,
дождитесь задачи и запросите `run(action="result", id=RUN_ID)`.

## Прочитать числа вместе с ограничениями

Прогноз целевых показателей возвращается по месяцам в их собственных единицах.
Для портфеля отчёт дополнительно содержит потери. Квантили P5, P50 и P95 — значения,
ниже которых лежит соответственно 5 %, 50 % и 95 % рассчитанных исходов;
P50 называют медианой.

![Учебная медиана и полоса центральных 90 процентов исходов каждого месяца](<../images/forecast-reading.ru.svg>)

Рисунок иллюстрирует чтение квантилей и не содержит результатов реального расчёта.
Полоса относится к каждому месяцу отдельно; её нельзя читать как обещание,
что 90 % траекторий целиком останутся внутри полосы.

У потерь положительное значение означает убыток, отрицательное — прибыль.
ES95 — средняя потеря в худших 5 % исходов. Сравните конец горизонта с потерями
по месяцам и наибольшей потерей на пути: восстановление к концу года не отменяет
убытка в середине года.

Цена сценария измеряет изменение распределения ради наблюдений при заданных
вмешательствах. Цена не равна вероятности события и не выражается в деньгах.
При одних вмешательствах математическая цена равна нулю, а программа не формирует
отдельный блок её оценки. Проверьте статус допуска расчёта, предупреждения,
исключённые позиции и покрытую долю стоимости до использования чисел в решении.

Проверка моделей на истории — отдельная операция `model(kind="macro", action="backtest")`.
Она оценивает прогнозы прошлых эпизодов и не запускается автоматически ради первого
расчёта. Смысл показателей и условия допуска объясняет [описание проверки моделей](<../../src/mst/metrics/README.md>),
а полные параметры вызовов — [справочник инструментов](<../reference/tools.md>).
