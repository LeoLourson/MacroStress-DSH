# Report on the project, 1–9 November 2026

On 1 November the project reached its first version fit for use. The system answers what happens to a portfolio if a given event occurs. A person names the event in words; an agent — a program that reads texts and fills a formal record — turns the description into a scenario; models build possible paths for the economy; and every position is repriced along those paths. The result is a distribution of losses by month rather than a single estimate, so a decision rests on the whole set of outcomes. The system, however, rested on conventions that were never written down, and the start of the month went into recording them and making the work follow them.

A common schema for the scenario appeared: what parts it has, what every number means, how an event taken from a source differs from an assumption. Every number carries a label — taken from the event text, from a named source, or an assumption — so a reader sees where fact ends and guesswork begins. The economy is split into levels: country, industry, company. Each level is computed from the paths of the level above, so an event travels down the chain to a particular security. The scenario price was introduced: a measure of how far the event departs from the ordinary picture of the world the models describe. The higher the price, the worse the event fits the models, and the system now says so itself. An admission threshold sits beside it: if the divergence or the error crosses the limit, the result is marked as unreliable. The scenario also carries a breakdown: how much of the loss came from the conditions of the event and how much from consequences the models do not contain and which were entered by hand. The reverse problem was added: set a loss level and find the event that reaches it at the lowest scenario price. Guides for the agent that assembles a scenario were written at the same time, together with checks that prevent saving an incomplete record.

On 2 November the work turned to the models of the economy. One of them distinguishes a calm state from a crisis state and switches between them. The models gained a stability limit: a version whose paths start to explode is rejected even if it explains the past well. The share price is now modelled in monthly changes rather than in levels, which removed a spurious long-run trend. A credit premium was added to the share price: a deterioration in the borrower's quality now reaches its share price. Every model gained a diagnostic that shows why a version failed a check. Before a calculation the system verifies that the models can serve every position and warns when an impact does not reach it.

Work on the reliability of the platform went alongside. A long calculation can be awaited in one call instead of polling its state in a loop. Stray output from a plugged-in model no longer breaks the communication channel. Data writing survives a file being read by another process at the same time. The platform contains no concrete models: they are plugged in separately, and a new model needs no changes to the platform itself. Decisions were recorded in separate notes with their reasons and consequences, so that a month later they need not be reconstructed from memory.

On 3 November the work turned to checking against the past. The forecast was compared with what actually happened, on historical episodes, with dates taken evenly across the calendar rather than chosen for convenience. The benchmark is a random walk: if a model is no better than simply continuing the last value, its advantage is small. Materials for checks were assembled: a plan for matching the models against history and questions used to evaluate the search over the source corpus. Version 1.0.2 came out the same day.

A second line of work began then and took the rest of the week. Historical data are not always enough, especially for rare events, and then knowledge can be gathered from an expert. A model appeared that builds a forecast from answers to questions. Questions come in small portions, answers are saved in parts, and an interrupted interview resumes from the same place. Every change in the scenario has an owner, so interviews can run in parallel and it is clear who filled in what. Answers are checked for economic consistency: if they contradict each other or a known relation between quantities, the system notices and asks for an explanation. On 5 November the team measured how much text an agent has to hold to complete an interview and added a way to continue after a network failure with the same agent.

Version 1.1.0 came out on 9 November. The interview mechanism became shared: any model can now pose its questions and receive answers in the same order. The check sets were gathered in one place, and a set of one hundred events that never happened in history was added; it tests how the agent builds a scenario. The guides for the agent were rewritten to match the current system.

In nine days the project moved from 1.0.0 to 1.1.0. The change concerns checks: an incomplete scenario is not saved, an unstable model version is not accepted, and a calculation without admission is not passed off as reliable. A way to use knowledge where data are scarce also appeared. The result can now be explained: it is visible where the loss came from, which part of the scenario caused it, and how far the answer depends on assumptions. Part of the work is unfinished: estimates of the new model versions and full checks against history are still ahead.
