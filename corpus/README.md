# Корпус сценариев

По этим материалам строится сценарий стресс-теста: здесь собраны методики регуляторов, их опубликованные сценарии, работы о передаче шоков и описания прошлых кризисов. Полный список лежит в [`manifest.json`](manifest.json). В git лежат манифест, `series.toml` и проверочные вопросы; скачанные оригиналы, тексты в Markdown и индекс — данные: они живут в `workspace/corpus/` и в git не попадают.

## Состав

| `kind` | Содержание | ID | Объём |
|---|---|---|---|
| `methodology` | выбор жёсткости сценария, горизонта и факторов, согласование путей, сателлитные модели | M1–M21 | 21 документ, 30 изданий |
| `scenario_set` | сценарии регуляторов с числами | S1–S7 | 7 серий, около 90 изданий |
| `transmission` | передача шоков в ставки, курс, кредит и спреды | T1–T5 | около 40 документов, отбираются по эпизодам |
| `episode` | ход прошлого кризиса | R1–R32, X1–X35, G1–G43 | 110 карточек |

Ряды D1–D5 (ЦБ, MOEX, FRED, МВФ IFS, BIS) в индекс не входят: скрипт считает по ним таблицы движений для карточек эпизодов. Какой ряд измеряет фактор в стране, задаёт [`series.toml`](series.toml). D4 (МВФ IFS) заменён рядами BIS того же содержания: курсы, ставки центральных банков, инфляция, цены жилья.

## Папки

В git:

```
corpus/
  manifest.json                 список корпуса и адреса оригиналов, правится руками
  series.toml                   ряды для таблиц движений и их привязка к факторам и странам
  eval/questions.md             проверочные вопросы для поиска
  templates/source.md           шаблон документа
  templates/episode.md          шаблон эпизода
```

В workspace (`--corpus workspace/corpus`, вне git) та же раскладка плюс всё, что пишут
команды:

```
workspace/corpus/
  manifest.json, series.toml, eval/, templates/   копия того, что выше
  downloads.json                что скачано: адрес, sha256, размер, дата; пишет fetch
  sources/methodology/M1.md     документ с одним изданием
  sources/scenario-sets/S1/2023.md   серия: файл на издание
  sources/transmission/T2/<slug>.md
  episodes/ru/R16.md            также em/ и dm/
  raw/<id>/<edition>.pdf        скачанные оригиналы
  text/<id>/<edition>.md        текст книг и журналов с text_policy: summary
  series/<series>.csv           дневные ряды D1–D5
  index/                        chunks.jsonl, vectors.npy, vectors.json, state.json
```

Путь файла задаёт поле `path` в манифесте, поэтому файл без записи в манифесте в индекс не попадёт.

## Сборка

Корпус собирает `mst.corpus` (`src/mst/corpus`); `--corpus` — корень корпуса в workspace:

```
python -m mst.corpus check --corpus DIR              что есть и чего не хватает
python -m mst.corpus fetch [ID ...] --corpus DIR     оригиналы в raw/, запись в downloads.json
python -m mst.corpus discover URL [--match RE]       ссылки на документы со страницы, чтобы дописать files
python -m mst.corpus add KEY FILE [--url URL] --corpus DIR   файл, скачанный руками, как будто его скачал fetch
python -m mst.corpus convert [ID ...] --corpus DIR   оригиналы в Markdown
python -m mst.corpus series [SERIES ...] --corpus DIR --store DIR  дневные ряды D1–D5 в series/
python -m mst.corpus episodes [ID ...] --corpus DIR --store DIR    карточки эпизодов
python -m mst.corpus index --corpus DIR              index/chunks.jsonl и векторы
python -m mst.corpus search QUERY --as-of DAY --corpus DIR  поиск
python -m mst.corpus eval --corpus DIR               recall@5 по eval/questions.md
python -m mst.corpus all --corpus DIR --store DIR    fetch, convert, series, episodes, index подряд
```

То же доступно инструментом `corpus`: `search`, `get`, `list` и `add` отвечают сразу, `index`
и `fetch` идут задачей на ресурсе `corpus`. `--store` — месячное хранилище рядов
(`workspace/series`): в него команды заглядывают, когда дневного ряда нет.

Адрес оригинала лежит в манифесте: у документа с одним изданием в поле `file`, у серии в `files` по изданиям. Адрес задаётся либо прямой ссылкой `url`, либо страницей `page` и регулярным выражением `match`: тогда берётся первая ссылка страницы, у которой адрес или текст подходит под выражение. Так скачиваются файлы, чей адрес меняется или неизвестен заранее. `format: html` означает, что документ — сама веб-страница. `published` задаёт дату публикации, если она известна от издателя. Издание без адреса `fetch` пропускает, а `check` его перечисляет; адрес для него подбирают через `discover`. Файл, который уже лежит на диске с хешем из `downloads.json`, повторно не скачивается.

FRED требует ключ в переменной `FRED_API_KEY`. Остальные источники ключа не требуют. imf.org отвечает 403 на запросы скриптов, поэтому M8–M11 и S7 скачиваются руками в браузере и регистрируются через `add`: `python -m mst.corpus add M11 wp1368.pdf --corpus workspace/corpus`. economy.gov.ru и iss.moex.com не отвечают на запросы из-за рубежа: прогнозы S3 взяты с копии на legalacts.ru, а ряды MOEX скачиваются, когда биржа отвечает.

## Статусы

| | `planned` | `raw` / `draft` | `ready` |
|---|---|---|---|
| документ | текста нет | текст извлечён `convert` и не вычитан; индексируется | вычитан, все издания на месте |
| эпизод | карточки нет | карточка с таблицей движений, хронология не написана; индексируется | хронология, механизм и источники написаны |

`convert` переводит источник из `planned` в `raw`, `episodes` переводит эпизод из `planned` в `draft`. Перевод в `ready` делается руками после вычитки.

## Документ

Файл в `sources/` начинается с YAML-шапки по [`templates/source.md`](templates/source.md), за которой идёт текст документа. Поле `published` содержит дату публикации с точностью до дня: по ней фильтр `as_of` скрывает документы, вышедшие позже даты прогона. `published_basis` говорит, откуда дата: `manifest` (поле `published` в адресе файла), `pdf_metadata` (дата создания PDF, если её год совпадает с годом издания) или `year_end` (31 декабря года издания, самая поздняя возможная дата, чтобы `as_of` не показал документ раньше времени). При `text_policy: full` хранится весь текст, а для книг и журналов по подписке ставится `summary` и пишется собственный конспект со ссылками на страницы. Текст таких источников `convert` кладёт в `<corpus>/text/`, а не в индекс: это материал для конспекта.

`convert` берёт текстовый слой PDF без распознавания. Страница-скан остаётся пустой и помечается `<!-- p. N: нет текстового слоя -->`; если таких страниц больше половины, `convert` сообщает, что файлу нужно распознавание. Номер страницы — метка, которую показывает PDF. Заголовки берутся из оглавления PDF, колонтитулы (строки, повторяющиеся на большинстве страниц) удаляются. Таблицы выходят строками текста, а не Markdown-таблицами: их перенос — часть вычитки при переводе в `ready`.

Заголовки оригинала переносятся как `#`–`####`, потому что по ним режется индекс. Перед текстом каждой страницы стоит комментарий `<!-- p. 12 -->`, чтобы цитату можно было дать со страницей. Таблицы сценариев переносятся Markdown-таблицами, и единицы указываются в заголовке столбца («Ключевая ставка, % годовых»). В `source_sha256` записывается хеш исходного файла, в `retrieved` — дата скачивания.

## Эпизод

Карточка `episodes/<region>/<ID>.md` по [`templates/episode.md`](templates/episode.md) описывает только то, что произошло, со ссылками на источники того времени. Каждое утверждение хронологии опирается на документ, вышедший в окне эпизода: пресс-релиз ЦБ, доклад, обзор.

Окно по умолчанию начинается за 3 месяца до `start` и заканчивается через 12 месяцев после. Таблицу «Движения факторов» и поля `movements` и `unmeasured` заполняет `python -m mst.corpus episodes` по рядам D1–D5, одинаково для всех эпизодов, и руками их не правят. Хронологию, механизм, аналогию и источники пишут руками, и повторный запуск их сохраняет. Поле `known_from` равно концу окна: раньше этой даты поиск эпизод не показывает, иначе сценарий для даты внутри кризиса строился бы с известной развязкой.

Для каждого фактора берётся первый ряд из `series.toml`, у которого есть данные и до `start`, и после. По нему считаются:

- база — последнее наблюдение до первого дня месяца `start`;
- экстремум — наблюдение от `start` до конца окна, дальше всего отстоящее от базы;
- изменение — экстремум минус база в п. п. для ставок и спредов, отношение экстремума к базе минус единица в процентах для курсов, индексов и цен;
- дней до экстремума — от первого дня месяца `start`;
- дней до восстановления — от экстремума до первого наблюдения, вернувшегося к уровню базы или перешедшего его; пусто, если в окне этого не случилось.

Фактор без рыночного ряда (ликвидность и капитал банков, потоки капитала, санкции, дефолт) попадает в `unmeasured` и описывается в хронологии. Пока дневные ряды не скачаны, берутся месячные ряды из `workspace/series` (`--store`), если `monthly` в `series.toml` их называет. Это ряды с 2012 года, и экстремум внутри месяца по ним не виден; таблица об этом пишет, а столбец «Ряд» помечает разрешение ряда.

## Фрагмент индекса

Каждая строка `index/chunks.jsonl` описывает один фрагмент:

| Поле | Значение |
|---|---|
| `chunk_id` | `S1/2023#3.2/1`: документ, издание, номер раздела, номер куска в разделе |
| `doc_id`, `edition`, `kind`, `region`, `jurisdiction` | из манифеста; `region` у документа — `ru` для российских, у остальных пусто |
| `visible_from` | `published` документа или `known_from` эпизода |
| `title` | заголовок `#` документа или карточки |
| `heading_path` | `["Рисковые сценарии", "Глобальный финансовый кризис"]` |
| `pages` | номера из комментариев `<!-- p. N -->` |
| `factors` | теги шапки |
| `text` | текст фрагмента |
| `sha256` | хеш нормализованного текста: по нему цитата сверяется с источником |

## Индексация

Индексатор читает манифест и пропускает записи со статусом `planned`, а запись `ready` без файла считает ошибкой; у записи `raw` недостающие издания только перечисляются. Документ режется по заголовкам до уровня `####`; токеном считается слово. Раздел длиннее 800 токенов делится по абзацам на куски по 300–800 токенов с перекрытием в один абзац. Таблица всегда остаётся в одном куске вместе с абзацем перед ней. Карточка эпизода режется по своим разделам, и таблица движений получается отдельным фрагментом. Перед хешированием текст приводится к NFC, пробелы схлопываются, комментарии страниц удаляются.

Поиск ранжирует фрагменты дважды: по BM25 над `title`, `heading_path` и `text` со стеммингом русского и английского и по косинусу векторов e5 (`index/vectors.npy`, их пишет `python -m mst.corpus index`). Два списка по 100 мест складываются по обратным рангам, $1/(60+r)$. Фильтры `visible_from <= as_of`, `kind`, `region` и `factors` применяются до ранжирования:

```
search(query, as_of, kind=None, region=None, factors=None, k=8) -> [chunk]
```

Тот же поиск доступен инструментом `corpus(action="search")`, а фрагмент по `chunk_id` —
`corpus(action="get")`. Оба фильтруют по той же дате `as_of` и сети не требуют:
`index/state.json` хранит дату сборки индекса и число фрагментов.

## Проверка поиска

В `eval/questions.md` лежат 20–30 вопросов, которые возникают при построении сценария, и для каждого — правильные `chunk_id`. Метрика — recall@5 по всем вопросам; любое изменение нарезки, стемминга или модели поиска сопровождается её пересчётом.

## Что в корпусе сейчас

- Источники: 141 из 150 файлов скачаны, 140 переведены в Markdown и имеют статус `raw`. Не
  скачаны M8–M11 и S7 (imf.org отдаёт 403 на запросы скриптов: файлы берутся в браузере и
  регистрируются через `add`), S3 за 2018–2019 (копии нет), M19 (русского текста МСФО 9 не
  нашлось), T5 (главы GFSR, imf.org). У M16 текст лежит в `<corpus>/text/`, конспект не
  написан.
- Эпизоды: 110 карточек с таблицами движений по дневным рядам, у 105 измерен хотя бы один
  фактор. Хронологии написаны у R1–R32 и X1–X35, у G1–G43 нет; все эпизоды в `draft`.
- Индекс: 7036 фрагментов с векторами, recall@5 = 0,271 на 24 размеченных вопросах. Вопросы об
  эпизодах находятся все (Q17–Q24); из 16 вопросов к документам — Q7, Q8 и Q15. Десять
  промахов приходятся на английские документы: русский запрос не достаёт ответ ни по BM25, ни
  по вектору e5-small.
