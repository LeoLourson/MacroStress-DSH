# Корпус источников для сценария

Корпус MacroStress — библиотека документов и описаний прошлых кризисов, по которой агент
обосновывает числа сценария стресс-теста. Корпус нужен, чтобы отличать опубликованное число
от собственного предположения и не использовать сведения, ещё неизвестные на дату расчёта.
Для работы с готовым корпусом начните с поиска; для сборки или проверки полноты используйте
команды из раздела «Сборка и обслуживание».

## Какие материалы входят в корпус

Состав задаёт [манифест](<manifest.json>) — перечень источников с адресами, изданиями,
путями и состоянием подготовки. Поле `kind` делит материалы по роли при построении сценария.

| Значение `kind` | Что искать | Семейство идентификаторов |
|---|---|---|
| `methodology` | Как выбрать тяжесть события, горизонт, факторы и согласованные пути показателей | `M` |
| `scenario_set` | Опубликованные регуляторами сценарии с числами | `S` |
| `transmission` | Как изменение одного показателя передаётся в ставки, курс, кредит и спреды — надбавки к доходности | `T` |
| `episode` | Что произошло во время исторического кризиса | `R`, `X`, `G` |

Ряды источников `D1`–`D5` в поисковый индекс не входят. По ним команда `episodes` заполняет
таблицы движений показателей в карточках кризисов. Привязку ряда к стране и фактору задаёт
[каталог рядов](<series.toml>). Каталог охватывает Банк России, Московскую биржу,
базу FRED Федерального резервного банка Сент-Луиса, Международный валютный фонд и Банк
международных расчётов (BIS). Для содержания `D4`, первоначально связанного со статистикой
МВФ IFS, используются ряды BIS: курсы, ставки центральных банков, инфляция и цены жилья.

## От оригинала до найденной цитаты

```text
Манифест с адресами
        │ fetch или add
        ▼
Оригинал + запись о загрузке
        │ convert
        ▼
Текст Markdown ── вычитка ──► проверенный текст
        │                           │
        └────────── index ──────────┘
                       ▼
              Фрагменты + векторы
                       │ search с датой as_of
                       ▼
              Цитата с источником

Ряды ── episodes ──► таблица движений ──► карточка кризиса ──► index
```

Схема показывает происхождение поисковой выдачи: загрузка сохраняет оригинал, извлечение
создаёт текст, а индексатор делит текст на фрагменты. Вычитка нужна даже после успешного
извлечения, поскольку поиск может вернуть ещё не проверенный текст со статусом `raw`.
У карточки кризиса таблица движений получается из рядов, а хронологию и механизм пишет человек.

В Git хранятся [манифест](<manifest.json>), [каталог рядов](<series.toml>) и
шаблоны [документа](<templates/source.md>) и [карточки кризиса](<templates/episode.md>).
Скачанные оригиналы, тексты и индекс относятся к данным отдельной рабочей области и в Git
не попадают. Рабочий корень корпуса содержит копии правил и производные файлы:

```text
workspace/corpus/
  manifest.json, series.toml, templates/   правила и каталог источников
  downloads.json                         адрес, SHA-256, размер и дата загрузки
  raw/<id>/<edition>.pdf                  оригиналы
  sources/methodology/M1.md               документ с одним изданием
  sources/scenario-sets/S1/2023.md         отдельное издание серии
  sources/transmission/T2/<slug>.md       работа о передаче шоков
  text/<id>/<edition>.md                  извлечение для будущего конспекта
  series/<series>.csv                     ряды для измерений
  episodes/ru/R16.md                      карточки; также em/ и dm/
  index/                                 фрагменты, векторы и состояние индекса
```

Регионы `ru`, `em` и `dm` обозначают Россию, развивающиеся рынки и развитые рынки с сырьём.
Путь каждого материала берётся из поля `path` манифеста; отдельный файл без записи в
манифесте не становится материалом поиска.

## Сборка и обслуживание

Команды выполняются из корня репозитория в установленном окружении Python. Реализацию
описывает [справочник mst.corpus](<../src/mst/corpus/README.md>). Аргумент `--corpus` задаёт
рабочий корень корпуса с копией манифеста, а `--store` — месячное хранилище рядов, к которому
карточки обращаются, когда нет дневного ряда. В примерах `DIR`, `ID`, `FILE`, `DAY`, `URL`
и `RE` — заменяемые обозначения пути, идентификатора, файла, даты, адреса и регулярного
выражения; квадратные скобки обозначают необязательный аргумент.

```text
python -m mst.corpus check --corpus DIR
python -m mst.corpus fetch [ID ...] --corpus DIR
python -m mst.corpus discover URL [--match RE]
python -m mst.corpus add KEY FILE [--url URL] --corpus DIR
python -m mst.corpus convert [ID ...] --corpus DIR
python -m mst.corpus series [SERIES ...] --corpus DIR --store DIR
python -m mst.corpus episodes [ID ...] --corpus DIR --store DIR
python -m mst.corpus index --corpus DIR
python -m mst.corpus search QUERY --as-of DAY --corpus DIR
python -m mst.corpus eval --corpus DIR --questions FILE
python -m mst.corpus all --corpus DIR --store DIR
```

Для полного цикла `all` последовательно выполняет `fetch`, `convert`, `series`, `episodes`
и `index`. Поэтапная сборка удобнее при вычитке или отказах источника: `fetch` загружает
оригиналы, `convert` извлекает текст, `series` получает ряды, а `episodes` обновляет карточки.
После изменения текста перестройте индекс командой `index`, иначе поиск продолжит читать
прежние фрагменты. Загрузка и полный цикл обращаются к внешним источникам; поиск по готовому
индексу работает локально.

Адрес оригинала у отдельного документа задаёт поле `file`, а у серии — поле `files` по
изданиям. Можно задать прямой `url` или сочетание `page` и `match`: загрузчик выберет первую
ссылку страницы, чей адрес или текст подходит под регулярное выражение. Команда `discover`
показывает кандидатов для заполнения манифеста. Формат `html` означает, что оригинал — сама
веб-страница, а `published` содержит известную издателю дату публикации.

Издание без адреса `fetch` пропускает, а `check` перечисляет. Файл с сохранённым контрольным
хешем SHA-256 из журнала загрузок повторно не скачивается. Если сайт запрещает автоматическую
загрузку, скачайте оригинал в браузере и зарегистрируйте через `add`; например:

```powershell
python -m mst.corpus add M11 wp1368.pdf --corpus workspace/corpus
```

Для FRED нужен ключ в переменной окружения `FRED_API_KEY`; остальным перечисленным
источникам ключ не требуется. Доступность сайта зависит от даты и места подключения.
Ответ `403` или отсутствие ответа следует диагностировать для конкретного адреса, а не
считать постоянным свойством всего корпуса. Загрузка вручную сохраняет происхождение файла,
но требует самостоятельной проверки издания и адреса.

Через протокол инструментов Model Context Protocol (MCP) тот же корпус доступен инструментом
`corpus`. Действия `search`, `get`, `list` и `add` возвращают ответ сразу, а `index` и `fetch`
создают фоновую задачу на ресурсе `corpus`; её состояние читают инструментом `jobs`.

## Когда текст можно считать проверенным

| Материал | `planned` | `raw` или `draft` | `ready` |
|---|---|---|---|
| Документ | Текста ещё нет | `raw`: текст извлечён и доступен поиску, но не вычитан | Текст вычитан, все издания на месте |
| Карточка кризиса | Карточки ещё нет | `draft`: таблица движений подготовлена, описание может быть неполным; карточка индексируется | Написаны хронология, механизм и источники |

Для полного текста `convert` меняет статус `planned` на `raw`, а `episodes` меняет статус
карточки с `planned` на `draft`. Статус `ready` ставят вручную после вычитки. Успешная
индексация подтверждает читаемость структуры, но не точность чисел, перевода или хронологии.

### Документ и дата его доступности

Документ начинается с YAML-шапки — блока служебных полей по
[шаблону источника](<templates/source.md>), — за которым идёт текст. Поле `published`
содержит дату публикации с точностью до дня. По дате публикации фильтр `as_of` исключает
документ, вышедший после даты расчёта. Поле `published_basis` объясняет происхождение даты:

| Значение | Основание |
|---|---|
| `manifest` | Дата `published` в описании файла манифеста |
| `pdf_metadata` | Дата создания PDF, если год совпадает с годом издания |
| `year_end` | 31 декабря года издания — консервативная граница, чтобы не показать документ раньше времени |

При `text_policy: full` в корпус входит полный текст. Для подписных книг и журналов
используется `summary`: человек пишет собственный конспект со ссылками на страницы.
Извлечение такого оригинала `convert` помещает в служебный каталог `text/`, а не в индекс;
материалом поиска становится подготовленный конспект.

Из PDF извлекается текстовый слой без распознавания сканов. Пустая страница получает
комментарий `<!-- p. N: нет текстового слоя -->`; если пустых страниц больше половины,
команда сообщает о необходимости распознавания. Метка страницы соответствует обозначению
в PDF. Заголовки берутся из оглавления, повторяющиеся колонтитулы удаляются, но таблицы
после извлечения могут остаться строками текста.

При вычитке сохраните заголовки оригинала уровнями `#`–`####`, поскольку по заголовкам
делится индекс. Перед текстом страницы сохраняйте комментарий вида `<!-- p. 12 -->`, чтобы
цитата содержала страницу. Числовые таблицы сценариев оформляйте Markdown-таблицами с
единицами в заголовках, например «Ставка центрального банка, % годовых». Поля `source_sha256` и
`retrieved` сохраняют хеш оригинала и дату загрузки.

### Карточка исторического кризиса

Карточка по [шаблону эпизода](<templates/episode.md>) описывает произошедшее со
ссылками на документы того времени. Каждое утверждение хронологии должно опираться на
источник, опубликованный в окне эпизода: пресс-релиз центрального банка, доклад или обзор.

По умолчанию окно начинается за три месяца до месяца `start` и заканчивается через
двенадцать месяцев после него. Команда `episodes` заполняет таблицу «Движения факторов» и
поля `movements` и `unmeasured`; вручную расчётные поля не меняют. Человек пишет хронологию,
механизм, аналогию и источники, а повторное обновление карточки сохраняет написанные разделы.
Поле `known_from` равно концу окна: до конца окна поиск скрывает карточку, чтобы описание
кризиса не сообщало агенту ещё неизвестную развязку.

Для каждого фактора берётся первый ряд из [каталога рядов](<series.toml>), у которого
есть наблюдения до и после `start`. Из ряда рассчитываются следующие величины:

- База — последнее наблюдение до первого дня месяца `start`.
- Экстремум — наблюдение от `start` до конца окна, дальше всего отстоящее от базы.
- Изменение — экстремум минус база в процентных пунктах для ставок и спредов; для курсов,
  индексов и цен — отношение экстремума к базе минус единица, выраженное в процентах.
- Дней до экстремума — расстояние от первого дня месяца `start`.
- Дней до восстановления — расстояние от экстремума до первого возвращения к базе или
  перехода через неё; поле пусто, если восстановления в окне не было.

Ликвидность и капитал банков, потоки капитала, санкции и дефолт могут не иметь подходящего
рыночного ряда. Такой фактор попадает в `unmeasured`, а его содержание раскрывают в
хронологии. При отсутствии дневных данных команда использует месячный ряд из `--store`,
если поле `monthly` каталога называет замену. Месячный ряд скрывает внутримесячный экстремум,
поэтому таблица помечает разрешение в столбце «Ряд»; доступный период зависит от хранилища.

## Что хранит индекс и как устроен поиск

Каждая строка поискового индекса описывает один фрагмент текста. Идентификатор `chunk_id`
вида `S1/2023#3.2/1` задаёт документ, издание, раздел и порядковый номер фрагмента раздела.
Остальные поля нужны для отбора и проверки найденной цитаты.

| Поле | Содержание |
|---|---|
| `doc_id`, `edition`, `kind`, `region`, `jurisdiction` | Идентификатор, издание, роль и география из манифеста; для российского документа `region` равен `ru`, для остальных документов пуст |
| `visible_from` | Дата `published` документа или `known_from` карточки |
| `title`, `heading_path` | Название и цепочка заголовков раздела |
| `pages` | Метки страниц из комментариев |
| `factors` | Тематические теги шапки |
| `text` | Текст фрагмента |
| `sha256` | Хеш нормализованного текста для сверки цитаты |

Индексатор пропускает записи `planned`. У записи `ready` индексатор считает отсутствие
файла ошибкой, а у `raw` перечисляет недостающие издания как ещё не подготовленные.
Индексатор делит документ по заголовкам до `####`; токен здесь означает слово. Раздел
длиннее 800 токенов он делит по абзацам на фрагменты по 300–800 токенов с перекрытием в
один абзац. Таблица остаётся в одном фрагменте вместе с предшествующим абзацем. Из карточки
индексатор выделяет разделы, причём таблица движений образует отдельный фрагмент. Перед
вычислением хеша индексатор приводит текст к форме Unicode NFC, схлопывает повторные
пробелы и удаляет комментарии страниц.

Поиск соединяет словарное и векторное ранжирование. Словарный алгоритм BM25 учитывает
название, цепочку заголовков и текст, приводя русские и английские слова к общим основам.
Векторная модель семейства e5 сравнивает смысловые представления запросов и фрагментов по
косинусной близости. В каждом списке берутся первые сто мест; вклад места `r` равен
`1 / (60 + r)`, а вклады двух списков складываются. Фильтры даты, `kind`, `region` и
`factors` применяются до ранжирования.

```text
search(query, as_of, kind=None, region=None, factors=None, k=8) -> [chunk]
```

Параметр `k` ограничивает число возвращаемых фрагментов. Поиск через `corpus(action="search")`
и чтение фрагмента через `corpus(action="get")` используют одну границу доступности
`visible_from <= as_of`; чтение по идентификатору не открывает будущий документ.

## Как проверить полноту и качество

Количество скачанных файлов, готовых карточек и фрагментов зависит от рабочей области,
поэтому фиксированное число в инструкции быстро устаревает. Для воспроизводимой проверки
полноты выполните локальную команду:

```powershell
python -m mst.corpus check --corpus workspace/corpus
```

Вывод показывает источники и издания, наличие адресов, загрузок и Markdown-текстов,
статусы карточек и число написанных хронологий. Состояние собранного индекса через MCP
показывает `jobs(action="state")`, а состав манифеста — `corpus(action="list")`.
Наличие фрагментов ещё не доказывает, что поиск возвращает нужный ответ.

Качество поиска измеряется отдельно на [размеченных вопросах](<../bench/corpus-search/questions.md>).
Метрика `recall@5` — средняя по размеченным вопросам доля правильных фрагментов, найденных
среди первых пяти результатов. Вопрос без списка правильных фрагментов в среднее не входит.
После изменения нарезки, словарной обработки или векторной модели заново проверьте разметку
и выполните:

```powershell
python -m mst.corpus eval --corpus workspace/corpus --questions bench/corpus-search/questions.md
```

В отчёте о качестве указывайте дату проверки, версию кода, состояние индекса и число
размеченных вопросов вместе со значением метрики. Старое значение без повторной проверки
не описывает качество изменённого корпуса. Правила хранения измерений находятся в
[описании проверочных наборов](<../bench/README.md>).
