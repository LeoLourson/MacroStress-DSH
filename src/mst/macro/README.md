# mst.macro

Макромодель разделов 2 и 4 [формализации](../../../docs/scenario-formalization.md): реестр
переменных и шоков, байесовская оценка VAR со стохастической волатильностью, знаковая
идентификация, условный прогноз сценария, его тяжесть и проверка на исторических эпизодах.

```powershell
python -m mst.macro estimate --as-of 2026-10-29 --store DIR --models DIR
python -m mst.macro backtest --as-of 2026-10-29 --store DIR --models DIR --corpus FILE
```

`estimate` собирает панель, известную на `--as-of`, оценивает модель, идентифицирует шоки и
пишет версию в `<models>/macro/<sha256>/`; печатает хеш и диагностику. `backtest` проверяет
модель на эпизодах `backtest.toml` и печатает покрытие $[P_5, P_{95}]$. Обе команды ничего не
загружают из сети.

| Файл | Что делает |
|---|---|
| `registry.toml`, `registry.py` | Реестр: 23 переменные с преобразованием $g$ и 5 именованных шоков с таблицей знаков |
| `spec.toml`, `spec.py` | Спецификация оценки: $T_0$, лаги, $\lambda$, волатильность, стационарные и сезонные переменные, сэмплер, дамми |
| `panel.py` | Панель: ряды на дату в шкале модели на сетке месяцев, глобальный блок первым, снятие сезонности, пропуски как NaN |
| `var.py` | Алгебра VAR: регрессоры, маска блочной экзогенности, импульсные отклики, итерация пути |
| `estimate.py` | Сэмплеры: сопряжённая BVAR (постоянная волатильность) и треугольный алгоритм со стохастической волатильностью; пропуски разыгрываются |
| `sv.py` | Шаги Гиббса для волатильности: смесь KSC, скорость $s_j$, множители $\omega$, степени свободы $\nu$ |
| `identify.py` | Знаковые ограничения: поиск поворота $Q$ по розыгрышам, отбрасывание неидентифицируемых |
| `forecast.py` | Условный прогноз `simulate` (раздел 4.3) и тяжесть `severity` (раздел 4.4) |
| `version.py` | Версия модели: сохранение, загрузка с проверкой хеша, список и описание |
| `backtest.toml`, `backtest.py` | Эпизоды проверки, сборка сценария из реализованных путей, покрытие, доля взрывных розыгрышей |
| `cli.py`, `__main__.py` | Команда `python -m mst.macro` |

Правка `registry.toml` или `spec.toml` действует только на новые версии: версия хранит
спецификацию, с которой оценена. Оценка детерминирована сидом `sampler.seed`.
