# mst.macro: общие показатели экономики и их история

Пакет `mst.macro` задаёт макропеременные, собирает их историю на дату расчёта и хранит версии макромоделей. Макропеременная — показатель экономики в целом, например валютный курс или процентная ставка. Макромодель строит совместное распределение будущих показателей; её математический метод принадлежит подключаемому плагину, поэтому пакет `mst.macro` не выбирает единственную экономическую модель.

## Реестр, панель и версия

[Реестр registry.toml](<registry.toml>) задаёт идентификатор, единицу, источник и преобразование каждой переменной. Префиксы `gl.` и `ru.` различают глобальные и российские показатели, но сами по себе не доказывают направление экономической связи: ограничения задаёт конкретная модель.

`identity` сохраняет исходную единицу, а `log100` переводит положительное значение в сто натуральных логарифмов. Модели используют логарифмическую шкалу внутри расчёта; ставка в процентах и логарифм цены не взаимозаменяемы. [Модуль registry.py](<registry.py>) задаёт прямой и обратный перевод.

Панель — прямоугольная таблица «месяц × переменная», которую строит [panel.py](<panel.py>) из публикаций, известных на заданную дату. Глобальные переменные располагаются первыми; неизвестное значение остаётся `NaN`, то есть пропуском, а не нулём. Для выбранных переменных панель удаляет повторяющийся календарный профиль, рассчитанный только по доступной истории.

Разные плагины могут оценивать свои модели по одинаковой истории. Сохранённая версия фиксирует результат одной оценки и панель, на которой модель получила параметры.

[Модуль version.py](<version.py>) сохраняет панель, дату, идентификаторы переменных, название модели и остальные метаданные с массивами. Загрузчик вызывает модель из `meta["model"]`; если нужного плагина нет, он отклоняет чтение версии. Хеш содержимого защищает от незаметного изменения сохранённых массивов, но совместимый код плагина всё равно нужен для их интерпретации.

## Операции

Оценкой и перечнем версий управляет [mst.models](<../models/README.md>). Из корня репозитория можно сначала узнать идентификаторы моделей, затем оценить выбранную на уже загруженной истории:

```powershell
uv run python -m mst.models catalog
uv run python -m mst.models estimate-macro rw.joint --as-of 2026-10-29 --store workspace/series --models workspace/models
uv run python -m mst.models list --models workspace/models
```

Дата в примере задаёт доступность публикаций, а не начало прогнозного горизонта. Начальный месяц путей — последний месяц панели, который может быть раньше даты расчёта из-за задержки публикаций.

Функция `base` в [version.py](<version.py>) возвращает квантили пустого сценария в шкале модели. Квантиль P50 — медиана, а P5 и P95 ограничивают центральные 90 % распределения; при чтении результата нужно различать модельную шкалу и исходные единицы прогноза. [Тесты макроплатформы](<../../../tests/macro/README.md>) проверяют панель и сохранение версии; отдельные наборы, например [tests/bvar](<../../../tests/bvar/README.md>), проверяют свойства конкретной модели.
