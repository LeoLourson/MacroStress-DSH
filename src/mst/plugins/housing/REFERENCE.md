# Модель позиции в недвижимости `housing.paths.v1`: справочник

Описание составлено по проектным документам, а не по коду: `docs/reference/platform.md`, `docs/howto/plugins.md`, `docs/concept/formalization.md`, `src/mst/plugin_sdk/README.md`, `src/mst/drivers/registry.toml`, `plans/canon-alignment.md`, `plans/satellite-models.md` и сообщения коммитов плагина. Где источники молчат, пробел вынесен в открытые вопросы и не заполнен.

## 1. Назначение и место в системе

Модель оценивает позицию типа `real_estate` (жилая недвижимость) на путях сценария драйвера `housing_price_*` — средней цены квадратного метра в регионе России на первичном рынке (`housing_price_primary`) или вторичном (`housing_price_secondary`) по данным Росстата. Изменение стоимости в каждом розыгрыше входит в потерю портфеля $\Delta_t$, её квантили P5/P50/P95 и $\mathrm{ES}_{95\%}$ на конце горизонта, по месяцам и по всему пути, а через них — в обратный стресс-тест. Модель чистая: она читает только пути, уже разыгранные сценарием.

## 2. Входы

| Вход | Смысл | Единица |
|---|---|---|
| `notional` | Текущая стоимость позиции, $N$ | миллионы валюты позиции |
| `currency` | Валюта позиции $c$; базовая валюта — рубль | код ISO |
| `codes.okato` | Регион объекта; по нему платформа находит региональный драйвер | — |
| `terms.market` | Рынок жилья $m\in\lbrace\text{primary},\text{secondary}\rbrace$; `docs/reference/platform.md` называет его входом модели; он выбирает драйвер `housing_price_m` | — |
| драйвер `housing_price_m` | Путь $h_{r,t}$ | руб. за м² |
| макропуть курса | $X_{r,t}$ при $c\ne\text{RUB}$ | руб. за единицу $c$ |

$R$ — число розыгрышей, $H$ — горизонт в месяцах, $t=0$ — месяц расчёта. Без `market` позиция отклоняется с именем поля: молчаливых умолчаний у `terms` нет.

## 3. Оценка

Явной формулы для недвижимости нет ни в одном источнике. Сообщение коммита «Port the calculation of positions» говорит, что позиция задаёт номинал, а модель читает пути; SDK даёт `relative` — отношение пути к его значению на $t=0$, и модель акции это отношение использует. Согласованная с этими источниками оценка, вынесенная ниже в открытые вопросы:

$$
V_{r,t}=N\,X_{r,t}\,\frac{h_{r,t}}{h_{r,0}},
$$

где для рублёвой позиции $X\equiv1$. Изменение стоимости к концу горизонта $\delta_r=V_{r,H}-V_{r,0}$, потеря $L_r=-\delta_r$. Объект переоценивается по средней цене метра в регионе, поэтому значение имеет только относительное движение рынка.

Модель читает последний столбец путей как конец горизонта, поэтому потеря к месяцу $t$ — тот же расчёт на путях, обрезанных по $t$ (`plans/canon-alignment.md`). Погашения у недвижимости нет. Без драйвера, например для региона без ряда, позиция остаётся без расчёта, статус `invalid` с именем величины и кодом.

## 4. Параметры

| Символ | Смысл | Значение | Источник |
|---|---|---|---|
| $N$ | Номинал | из позиции | `Position.notional` |
| $m$ | Рынок | из `terms.market`, умолчания нет | `docs/reference/platform.md` |
| $h_{r,t}$ | Путь цены квадратного метра | из сателлитной версии | драйвер `housing_price_m` |
| $X_{r,t}$ | Путь курса | из макроверсии | `fx.py` |
| дисконт при продаже, арендный доход, износ | — | проектом не задано | — |

## 5. Выходы

`CalculationResult` по контракту SDK: статус `ok`, `needs_review` или `invalid`; `value_change` длины $R$ со значениями $\delta_r$; метрики с id `housing.<имя>`, значение или P5/P50/P95, у метрики потерь ещё ES95; пометки драйвера добавляет платформа через `envelope`.

## 6. Допущения и границы применимости

- Объект движется вместе со средней по региону: качества объекта, места внутри региона и ликвидности в модели нет.
- Драйвер квартальный (`span = 3` в `registry.toml`): месяцы между кварталами разыгрывает сателлит, а ряд начинается с 2021 года, так что история коротка.
- По `plans/satellite-models.md` больше 90 % путей цены жилья выходят из обучающего диапазона узла, и результаты в основном — экстраполяция.
- Ряд публикуется с лагом около 35 дней и пересматривается, поэтому $h_{r,0}$ — оценка.

## 7. Проверки, которые код должен пройти

1. При `market = primary` модель требует `housing_price_primary`, при `secondary` — `housing_price_secondary`.
2. Отсутствующее или иное значение `market` отклоняется с именем поля.
3. Для рублёвой позиции на фиксированных путях $\delta_r=N\,(h_{r,H}/h_{r,0}-1)$, если формула раздела об оценке подтвердится.
4. На постоянных путях $\delta_r=0$.
5. В `value_change` $R$ значений; повтор на тех же путях побитно тот же.
6. Расчёт на путях, обрезанных по месяцу $t$, даёт изменение стоимости к месяцу $t$.
7. Регион (`okato`) без драйвера даёт `invalid` с именем величины и кодом.
8. $h_{r,0}=0$ отклоняется с диагностикой.
9. У метрики потерь есть P5, P50, P95 и ES95.

## 8. Открытые вопросы и противоречия

1. Формула оценки не записана ни в одном источнике; отношение цен выведено из помощника SDK `relative` и модели акции.
2. Допустимые значения `market`: id драйверов подсказывают `primary` и `secondary`, точное написание в `terms` не задано.
3. Сопоставление региона: единственный ли это код `okato` и переходит ли отсутствующий регион на федеральный уровень (`registry.toml` говорит, что драйвер без ряда берёт параметры уровня выше), для позиций не сказано.
4. Издержки сделки и срок продажи в стрессе не заданы.
5. Валюта: у нерублёвой позиции с рублёвым драйвером тот же вопрос о двойном учёте курса, что у акции.
6. Знак потери и имена метрик прямо не записаны.
