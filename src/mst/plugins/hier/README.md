# Иерархическая модель драйверов `hier.gibbs`

Модель `hier.gibbs` переводит пути экономики в совместные пути показателей компаний, отраслей и регионов. Такой показатель называется *драйвером*, если по нему оценивается объект: цена акции определяет стоимость позиции в акции, а доля просроченных кредитов отрасли влияет на оценку кредитной позиции. Для объектов с короткой историей модель использует информацию родственных объектов, не приравнивая их коэффициенты полностью.

Иерархия объектов отличается от уровней системы. Уровень системы задаёт направление расчёта «экономика → драйвер → стоимость», а дерево объектов объединяет родственные ряды одной величины, например рынок акций, отрасль и компанию. Драйверы компании не меняют экономику, которая уже рассчитана.

## Уровни или месячные изменения

Уравнение содержит постоянную, собственное прошлое драйвера, текущие макропеременные и макропеременные прошлого месяца. Для величин из `differences` в [спецификации](<spec.toml>) уравнение применяется к изменениям:

$$
\Delta d_t = c + \rho\,\Delta d_{t-1} + \beta_0^\top \Delta x_t + \beta_1^\top \Delta x_{t-1} + e_t.
$$

Здесь $d_t$ — драйвер в шкале модели, $x_t$ — вектор входных показателей, $\Delta$ — разность соседних месяцев, $c$ — месячный дрейф, $\rho$ — коэффициент собственного прошлого, $\beta_0,\beta_1$ — коэффициенты входов, $e_t$ — случайный остаток. Если цена записана как $100\ln X$, разность примерно равна процентному изменению; коэффициенты при логарифмических входах тогда описывают эластичности.

Цена акции `share_price` оценивается в изменениях. Прогноз накапливает изменения от последнего известного уровня, а проверка ошибки и выхода за обучающий диапазон остаётся в уровнях. Цены жилья с квартальным наблюдением, спреды облигаций и доли просрочки оцениваются в уровнях. Выбор формы меняет смысл постоянной: у изменения постоянная задаёт тренд, а у уровня участвует в уровне притяжения.

## Оценка и проверка полезности макропеременных

Коэффициенты объекта распределены вокруг коэффициентов родителя; при короткой истории объект сильнее опирается на родителя. Алгоритм Гиббса по очереди строит условные выборки коэффициентов, разброса и ненаблюдаемых месяцев. Ограничение `rho_max` удерживает собственный лаг в стационарной области, то есть не допускает нарастания отклика на собственный остаток.

Чтобы проверить модель перед публикацией обслуживания, часть истории откладывается. Модель прогнозирует драйвер по фактическим макровходам и сравнивается с авторегрессией AR(1), которая знает только прошлое самого драйвера. Критерий — среднеквадратичная ошибка, RMSE. Если макровходы не улучшают прогноз, собственная модель объекта не используется; проверенный родитель может обслужить объект с соответствующей пометкой. То, что оценка прошла успешно, ещё не означает обслуживания.

Остатки разных драйверов коррелированы: общая корреляционная матрица версии сохраняет совместные движения, не объяснённые макровходами. При сборке нескольких сателлитных моделей платформа передаёт общий массив `shocks`; если игнорировать массив, корреляция между моделями разрушилась бы.

## Сценарий и подключение

Вмешательство на макроуровне доходит до драйвера через входы $x_t$. Вмешательство на сам драйвер применяется к готовому уровню после рекурсии: установка заменяет значение, сдвиг прибавляется. В форме по умолчанию изменение не попадает в собственный лаг и не продолжается в следующих месяцах автоматически. Различие формы и рекурсии определяет [общая формализация](<../../../../docs/concept/formalization.md>).

Если одну величину заявляют несколько установленных моделей, выбор нужно назвать явно:

```powershell
python -m mst.models estimate-satellites --model QUANTITY=hier.gibbs --macro MACRO --models MODELS --store STORE --drivers DRIVERS
```

Имена `QUANTITY`, `MACRO`, `MODELS`, `STORE` и `DRIVERS` нужно заменить величиной, версией макромодели и путями своей задачи. Подготовку и назначение величин описывает [пакет драйверов](<../../drivers/README.md>), а полный порядок первого расчёта — [первый сеанс](<../../../../docs/howto/first-session.md>).
