# mst.drivers: показатели отдельных объектов

Пакет `mst.drivers` связывает общие показатели экономики с показателями конкретных объектов. Величина задаёт вид измерения, например цену акции; объект задаёт компанию или отрасль; драйвер соединяет величину с объектом, например `share_price:sber`. Сателлитная модель строит пути драйвера по путям более общих показателей, а модель позиции использует драйвер для расчёта стоимости.

## От объекта к пути

[Реестр registry.toml](<registry.toml>) задаёт единицы величин, преобразования, входные показатели и уровни. Уровень 0 содержит макропеременные; величина уровня 1 читает макропеременные, а величина уровня 2 может читать ещё и величины уровня 1. Правило [registry.py](<registry.py>) запрещает входы собственного уровня и уровней с большими номерами, чтобы пути можно было строить последовательно.

![Модели от экономики к показателям объектов](<../../../docs/images/model-levels.ru.svg>)

Учебная схема показывает направление зависимости: сначала экономика, затем показатели объектов и стоимость позиций. Конкретная связь возникает только при наличии соответствующего входа в модели; изменение ставки не обязано одинаково менять все драйверы.

[Каталоги объектов](<catalogs/README.md>) находят объекты у источника и объявляют загрузчики их истории. [Обновление update.py](<update.py>) загружает ряды и сохраняет каталог драйверов; если каталог величины завершился ошибкой, прежняя запись величины сохраняется. Контракты объектов и имён драйверов находятся в [objects.py](<objects.py>).

[Подготовка history.py](<history.py>) выравнивает историю драйверов по месяцам панели макроверсии и строит входы модели. Преобразования `identity`, `log100` и `logit` означают исходную шкалу, сто натуральных логарифмов положительной величины и логарифм отношения доли к её дополнению. Последнее преобразование требует доли строго между нулём и единицей.

## Обновление и оценка

Из корня репозитория обновление одной величины выполняется так:

```powershell
uv run python -m mst.drivers update share_price --store workspace/series --drivers workspace/drivers/catalog.json
```

Команда обращается к источникам и записывает историю. Оценка сателлитов — отдельная операция [mst.models](<../models/README.md>), которой нужна сохранённая макроверсия:

```powershell
uv run python -m mst.models estimate-satellites --macro SHA256 --store workspace/series --models workspace/models --drivers workspace/drivers/catalog.json
```

Вместо `SHA256` укажите полный хеш из списка версий. Если несколько моделей объявляют одну величину, повторяемый параметр `--model QUANTITY=MODEL_ID` выбирает модель явно; автоматического выбора по порядку обнаружения нет.

## Что фиксирует сателлитная версия

[Модуль bundle.py](<bundle.py>) собирает части величин, назначенные модели, проверки драйверов и матрицу связи ошибок моделей в одну версию. Матрица нужна, чтобы ошибки разных драйверов одного уровня не разыгрывались независимо вопреки измеренной связи. По разным уровням случайные остатки разыгрываются независимо, а зависимость путей передаётся через входы моделей.

`served()` возвращает драйверы, которые версия может рассчитывать по сохранённым проверкам. Отсутствующий или отклонённый драйвер не заменяется нулём; причина отказа доходит до позиции и отчёта. Выход пути за диапазон истории помечается `outside_training_range`, но такая пометка сама по себе не подтверждает качество хвоста прогноза.

Новая величина требует записи реестра и подходящего каталога, а новая модель существующей величины подключается как плагин. Данные, сборка нескольких моделей и последовательность уровней проверяются в [tests/drivers](<../../../tests/drivers/README.md>); свойства иерархической модели отделены в [tests/hier](<../../../tests/hier/README.md>).
