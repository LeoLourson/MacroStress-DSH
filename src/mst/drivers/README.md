# mst.drivers

Величины объектов и их драйверы (раздел 6 формализации): реестр величин с каталогами
объектов, подготовка истории на панели макроверсии и сборка сателлитной версии из оценок
нескольких моделей. Сами сателлитные модели — подключаемые плагины: иерархический Гиббс
живёт в [mst.plugins.hier](../plugins/hier/README.md), ещё одна модель — отдельный пакет,
который обслуживает свои величины; величину могут заявить несколько моделей, и тогда
оценивающую называет явное `--model ВЕЛИЧИНА=МОДЕЛЬ`.

```powershell
python -m mst.drivers update [QUANTITY ...] --store DIR --drivers FILE
python -m mst.models estimate-satellites --macro SHA256 --store DIR --models DIR --drivers FILE [--model QUANTITY=MODEL_ID]
```

`update` запускает каталог каждой величины, загружает ряды найденных объектов и пишет
драйверы с историей в `--drivers` (`workspace/drivers/catalog.json`).
`estimate-satellites` собирает бандл версии: каждая величина оценивается назначенной ей
моделью, части и корреляция остатков образуют одну версию. Запускать только через
`python -m`: `__main__.py` ставит `OPENBLAS_NUM_THREADS=1`.

| Файл | Что делает |
|---|---|
| `registry.toml`, `registry.py` | Величины: единица, преобразование (`identity`, `log100`, `logit`), регрессоры и признаки $\max(0, y-c)$, лаги, `span`, каталог. Объекты и драйверы из каталога добавляются при загрузке; `match` и `resolve` находят драйвер позиции по коду |
| `objects.py` | Контракты объекта (класс, родитель, коды) и драйвера `<величина>:<объект>`; ряд драйвера — `drv.<величина>.<объект>` |
| `catalogs/` | Каталоги объектов по источникам, см. [catalogs/README.md](catalogs/README.md) |
| `update.py` | Каталог → загрузка рядов через `mst.data` → `catalog.json`. Упавший каталог сохраняет прошлую запись величины |
| `history.py` | История величины на панели: месяцы, дерево объектов, наблюдения в шкале модели, `x` из регрессоров и признаков; `x` из путей симуляции; корреляция остатков |
| `bundle.py` | Сателлитная версия из частей: сборка (`assemble`), сохранение и загрузка с диспетчеризацией по модели, `served` по проверкам, симуляция драйверов их моделями, пометка выхода за диапазон обучения |

Новый объект существующего источника появляется сам при следующем `update`. Новая величина —
таблица `[[quantities]]` в `registry.toml`; если у её источника нет каталога, нужен новый
класс в `catalogs/`. Новая сателлитная модель той же величины — плагин с явным назначением.
