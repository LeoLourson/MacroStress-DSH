# mst.scenario

Сценарий стресс-теста $(N, m, O, D, \mathcal C)$ из раздела 3
[канона](../../../docs/concept/formalization.md): нарратив $N$ с источниками, версии моделей
$m$, воздействия $O$, причины $D$ (координаты $\omega$ сверх параметров — шоки и скрытые
координаты) и условия $\mathcal C$ — на носитель, на средние и на вероятности, любого уровня.
Сценарий — файл `workspace/scenarios/<id>.json`; расчёт строит из него пути $R \times (H+1)$.

| Файл | Что делает |
|---|---|
| `contracts.py` | `Scenario` (с `causes`, `regime_event`, `expectations`, `probabilities`, `inner`, `approved_by`), `Constraint` (интервал `low < high` или точка `value`, базис), `Term` (макропеременная или драйвер `<quantity>:<object>`), `Expectation`, `ProbabilityCondition`, `Impact`; месяц за горизонтом, смешанное условие, повтор переменной — отказ |
| `spec.py` | Файл `scenarios/<id>.json`: тот же `Scenario` плюс хеши макроверсии и сателлитов, на которых он считается |
| `build.py` | `build`: условный прогноз макромоделью-плагином (план $C, D$ с расширенными точками), воздействия на макропеременные входят в путь до сателлитов, наклон причин под условия на средние (`overlay`), бандл `mst.drivers` симулирует драйверы по уровням, условия на нижних уровнях несут веса внутри групп $R$; цена $\mathrm{dist}(s) = \mathbb E_P[-\log P(S \mid R)]$ с разложением по уровням. `validate` называет каждую невыполнимую связку, неизвестную причину, отсутствие утверждения и воздействия на неизвестные цели |
| `overlay.py` | `solve_lambda`: выпуклая двойственная задача наклона $e^{\lambda'f}$ (L-BFGS-B, знаковые границы односторонних условий) — веса внутри групп $R$, цена, эффективный размер, достижимость; `resample` — систематический ресэмплинг внутри групп |
| `reverse.py` | Обратная задача канона (раздел 6): `Family` с фиксированными $m, O, D$, `sup_rho` под ценой $\kappa$ и `inf_dist` над уровнем $L^*$; `python -m mst.scenario reverse` |
| `tool.py` | Операции инструмента `scenario`: `list`, `get`, `save`, `reverse`, `validate` |

Границы ограничений — в шкале модели $y=g(X)$: для ставки проценты, для курса $100\ln X$.
Имена переменных сверяет реестр `mst.macro.registry`, имена шоков — макроверсия ($J$ — свойство модели).

Пути (`Paths` в `build.py`) — $R$ розыгрышей на $H$ месяцев: макропеременные и драйверы в
исходных единицах, пометки путей драйверов (воздействие, параметры сверху, приблизительные
данные, выход за диапазон обучения), цена сценария с разложением по уровням, эффективный
размер наклона и проверки наложенного. Модели позиций читают их одной и той же формой.

Проверки `validate`:

- неизвестная переменная или шок — по реестру `src/mst/macro/registry.toml`;
- связанность ограничений: строка, которую причины не могут сдвинуть сами, — отказ с
  номером ограничения;
- воздействие на переменную, которой нет в макроверсии, и на драйвер, который бандл не обслуживает, — с причиной отказа;
- сателлиты другой макроверсии — с обоими месяцами;
- фрагмент корпуса, указанный в сценарии, вышел позже даты расчёта, — если индекс корпуса
  собран.

Тесты — [../../../tests/scenario](../../../tests/scenario/).
