# mst.scenario: событие как вход расчёта

Пакет `mst.scenario` хранит описание события, переводит его числа в шкалы моделей и строит пути при заданных вмешательствах и наблюдениях. Вмешательство задаёт значение извне, например решение центрального банка о ставке; наблюдение сообщает исход, например диапазон валютного курса после события. Различие влияет на расчёт: решение меняет построение путей, а наблюдение меняет вероятности исходов при уже заданных решениях.

Файл сценария содержит `narrative`, `sources`, `interventions`, `observations` и `approved_by`. Версии моделей, число путей и горизонт принадлежат запросу расчёта, поэтому описание события не привязано к одному математическому методу. [Общая схема](<../../../docs/concept/formalization.md>) задаёт нормативные определения и границы интерпретации.

## Что записывает автор

[Контракты contracts.py](<contracts.py>) требуют календарные месяцы `YYYY-MM` и исходные единицы величин. Вмешательство называет `quantity`, `months`, `kind`, `values`, `unit`, `reason`, `basis`; одна пара «величина — месяц» не может входить в два вмешательства. `set` устанавливает значение, а `shift` задаёт сдвиг в выбранной единице.

| Поле `unit` | Смысл |
| --- | --- |
| `level` | Значение в исходной единице величины |
| `change` | Изменение от последнего известного значения в той же единице |
| `percent` | Относительное изменение в процентах для величины в шкале `log100` |

Для `shift` на логарифмической величине функция [shift_to_scale](<translate.py>) переводит денежный сдвиг в постоянное смещение модельной координаты относительно последнего известного уровня. Функция не добавляет одинаковую денежную сумму к каждому случайному пути.

Наблюдение состоит из взвешенных членов `Term` с величиной и месяцем. `constraint` задаёт интервал `low < high` либо значение `value`; `expectation` ограничивает среднее; `probability` требует, чтобы вероятность попадания в интервал была не меньше `at_least`. Переводчик расширяет точное наблюдение до малого допуска, измеренного по истории, тогда как установленное вмешательством значение допуска не требует.

Каждый численный элемент содержит `basis`: `event`, если число прямо задано событием; список идентификаторов фрагментов, если число приведено в источнике; `assumption`, если число выбрано автором. Свободный текст причины не заменяет основания. Поле `approved_by` заполняет утверждающий сценарий человек, а не расчётная модель.

## Учебный пример контракта

Пример проверяет форму без сохранения и расчёта. Ставка 15 % в октябре 2026 года задана учебным условием; поле утверждения оставлено пустым намеренно:

```python
from mst.scenario.contracts import Scenario

scenario = Scenario.model_validate({
    "narrative": "Учебное решение по ставке; не прогноз",
    "interventions": [{
        "quantity": "ru.key_rate", "months": ["2026-10"],
        "kind": "set", "values": [15.0], "unit": "level",
        "reason": "учебный пример", "basis": "assumption"
    }],
    "observations": [], "approved_by": None
})
assert scenario.interventions[0].kind == "set"
```

Проверка формы не подтверждает, что октябрь входит в горизонт выбранной версии. Календарь начинается от последнего месяца панели модели, а не от дня запуска.

Значение вмешательства может быть числом, объектом `{"uniform": [low, high]}` или `{"with_probability": p, "value": value}`. Первый закон равномерно выбирает значение, второй включает записанное значение с вероятностью `p`, иначе оставляет модельную координату нетронутой. Генератор выбирает реализацию закона один раз на группу путей отдельным потоком; добавление наблюдения не меняет уже разыгранных значений вмешательства.

## Как строятся пути

[Модуль context.py](<context.py>) собирает шкалы и последние известные значения, [translate.py](<translate.py>) создаёт численный план, а [build.py](<build.py>) вызывает макромодель, затем сателлиты по уровням. В форме по умолчанию макровмешательство применяется после розыгрыша; модель с рекурсивной структурной формой исполняет вмешательство сама.

[Модуль overlay.py](<overlay.py>) выполняет наблюдения на средние и вероятности, меняя веса путей внутри групп. Наблюдения на драйверы требуют `inner >= 2`; отсутствие подходящего пути хотя бы в одной сохраняемой группе означает противоречие моделей и сценария на используемой выборке. Поле `inner` — число путей с общими параметрами и реализацией вмешательств, а `draws` задаёт число таких групп.

Результат `Paths` содержит совместные макропути и драйверы в исходных единицах, проверки наблюдений и диагностики моделей. Математическая цена сценария без наблюдений равна нулю; отдельный блок оценки цены в таком расчёте не формируется и представлен `None`. Для наблюдений цена сопровождается стандартной ошибкой и доступным разложением по уровням; цена не равна денежной потере.

## Проверка, перенос и обратная задача

`validate` проверяет утверждение человеком, перевод единиц и месяцев, согласованность макро- и сателлитной версий и доступность цитируемых фрагментов на дату. Ответ содержит `problems`, `labels` и `warnings`: отсутствие источников и полностью предположительный сценарий раскрываются отдельно от ошибок формы. Проверка не заменяет полный расчёт: при доступном индексе проверяются адреса источников, но истинность их экономического прочтения остаётся обязанностью автора.

[Операции tool.py](<tool.py>) сохраняют и читают сценарии; [legacy.py](<legacy.py>) переводит прежний формат без изменения файла, а [migrate.py](<migrate.py>) переносит каталог с предварительной проверкой. Несовместимое наблюдение, которое нельзя точно выразить новым контрактом, должно быть разобрано, а не молча упрощено.

[Обратная задача reverse.py](<reverse.py>) ищет наиболее тяжёлый сценарий при ограничении цены либо минимальную цену достижения потери. Семейство фиксирует вмешательства и меняет наблюдения, потому что вмешательства сами не несут цены. Параметры команд можно посмотреть без изменения данных:

```powershell
uv run python -m mst.scenario --help
uv run python -m mst.scenario reverse --help
```

[Тесты сценариев](<../../../tests/scenario/README.md>) проверяют форму, перевод, случайные вмешательства, построение путей и обратную задачу. [Опорные образцы golden](<../../../tests/scenario/golden/README.md>) закрепляют побитовое поведение, но не заменяют экономическую проверку сценария.
