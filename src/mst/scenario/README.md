# mst.scenario

Сценарий стресс-теста $(N, C, D, O)$ из раздела 3
[формализации](../../../docs/scenario-formalization.md): нарратив $N$, ограничения $C$ на
пути макропеременных, движущие шоки $D$ и надбавки $O$ к драйверам. Сценарий — файл
`workspace/scenarios/<id>.json`; прогон строит из него пути $R \times (H+1)$.

| Файл | Что делает |
|---|---|
| `contracts.py` | `Scenario`, `Constraint` (веса, границы в шкале $y=g(X)$), `Term`, `Overlay`; месяц за горизонтом, `low > high`, повтор переменной в месяце — отказ |
| `spec.py` | Файл `scenarios/<id>.json`: тот же `Scenario` плюс хеши макроверсии и сателлитов, на которых он считается |
| `build.py` | `build`: условный прогноз `mst.macro` с ограничениями, обратно в исходные единицы, затем `mst.drivers.simulate` на тех же розыгрышах с надбавками; тяжесть $\delta$ — из безусловного прогноза той же версии. `validate` называет каждую невыполнимую связку |
| `tool.py` | Операции инструмента `scenario`: `list`, `get`, `save`, `validate` |

Границы ограничений — в шкале модели $y=g(X)$: для ставки проценты, для курса $100\ln X$.
Имена переменных и шоков сверяет с реестром `mst.macro.registry.Registry.check`.

Пути (`Paths` в `build.py`) — $R$ розыгрышей на $H$ месяцев: макропеременные и драйверы в
исходных единицах, пометки путей драйверов (надбавка, параметры сверху, приблизительные
данные) и тяжесть сценария. Модели позиций (шаг 8) читают их одной и той же формой.

Проверки `validate`:

- неизвестная переменная или шок — по реестру `src/mst/macro/registry.toml`;
- связанность ограничений: строка, которую движущие шоки не могут сдвинуть сами, — отказ с
  номером ограничения;
- надбавка на драйвер, который сателлиты не обслуживают, — с причиной отказа;
- сателлиты другой макроверсии — с обоими месяцами;
- сосланный фрагмент корпуса, вышедший позже даты расчёта, — если индекс корпуса собран.

Тесты — [../../../tests/scenario](../../../tests/scenario/).
