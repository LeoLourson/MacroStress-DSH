# mst.engine: расчёт стоимости позиций

Пакет `mst.engine` выбирает модель для позиции портфеля, готовит её входы и проверяет результат. Позиция — объект вложения с типом инструмента, текущей стоимостью и кодами для поиска данных; пути — совместные значения показателей по месяцам и случайным исходам. Движок получает готовые пути, поэтому не оценивает макромодель и не загружает рыночную историю.

## Путь одной позиции

```mermaid
flowchart LR
    P[Позиция] --> M[Выбор модели]
    M --> R[Требования модели]
    R --> I[Подготовленные входы]
    I --> V[Проверка входов]
    V --> C[Расчёт на общих путях]
    C --> O[Проверка результата]
    V --> E[Отказ с причиной]
    O --> E
```

Схема показывает обязанности платформы: модель объявляет потребности, движок разрешает имена и коды, а отказ остаётся результатом позиции с объяснением.

[Каталог model_catalog.py](<model_catalog.py>) выбирает модель по `Position.type`. Отсутствие модели и несколько моделей одного типа дают отказ с именами; автоматического выбора одной из конкурирующих позиционных моделей нет. Реестр читается при первом обращении, чтобы диагностика сломанного плагина могла запуститься отдельно от расчёта.

Функция `prepare` в [dispatch.py](<dispatch.py>) проверяет `terms` по схеме модели, запрашивает `requirements` и сопоставляет нужные драйверы по объекту или кодам позиции. Драйвер — показатель объекта, например цена акции; он должен входить в обслуживаемый набор сателлитной версии. Отсутствующие макропеременная, валютный курс или обязательный драйвер получают отдельную диагностику.

Затем `calculate` вызывает модель и сверяет идентификаторы, валюту, текущую стоимость, длину массива изменений и объявленные метрики. Исключение на этапе `validate` или `calculate` превращается в статус `invalid` с кодом `model_error:<Тип>`, чтобы ошибка одной модели не остановила расчёт остальных позиций. Контракт не следует понимать как изоляцию от любого возможного сбоя импорта или подготовки.

## Набор результатов и статусы

[Модуль run.py](<run.py>) рассчитывает все позиции на одном наборе путей и возвращает `Batch` в исходном порядке позиций. [Модуль status.py](<status.py>) задаёт порядок `ok`, `needs_review`, `invalid`: результату набора присваивается худший статус.

`ok` означает отсутствие зарегистрированных проблем расчёта, `needs_review` требует проверки предупреждений, а `invalid` означает, что позиция не рассчитана. [Отчёт портфеля](<../portfolio/README.md>) включает `needs_review` в сумму, исключает `invalid` с причиной и отдельно показывает покрытие стоимости. Успешный статус движка не доказывает историческую точность модели.

## Проверенный пример

Самодостаточный демонстрационный расчёт акции можно выполнить из корня репозитория:

```powershell
uv run python -m mst.plugin demo-run equity
```

Входы демонстрации заданы в [объявлении equity](<../plugins/equity/plugin.py>), поэтому команда не оценивает новые модели и не требует сетевой истории. Для собственной модели используйте [контракт plugin_sdk](<../plugin_sdk/README.md>) и [порядок создания плагина](<../../../docs/howto/plugins.md>). Выбор модели, отказы и проверка формы результата покрыты [tests/engine](<../../../tests/engine/README.md>).
