# mst.corpus: источники для сценариев

Пакет `mst.corpus` хранит документы, из которых автор сценария берёт основания для чисел, и находит подходящие фрагменты на выбранную дату. Корпус — собрание источников с датами и происхождением; манифест — перечень документов и адресов; эпизод — карточка исторического события с измеренными движениями показателей. Поиск помогает найти основание, но не подтверждает автоматически, что найденный текст обосновывает выбранное число.

## Как готовится материал для поиска

```mermaid
flowchart LR
    M[Манифест источников] --> F[Оригиналы документов]
    F --> T[Текст с датой публикации]
    T --> I[Индекс фрагментов]
    E[Карточки эпизодов] --> I
    I --> Q[Поиск на дату]
```

Схема показывает подготовку корпуса: оригинал сохраняется отдельно от извлечённого текста, а поиск читает индекс, собранный из текстов и карточек эпизодов.

[Модуль manifest.py](<manifest.py>) задаёт источники, издания, документы и карточки эпизодов. [Загрузка fetch.py](<fetch.py>) сохраняет оригиналы с хешем и датой получения, а [convert.py](<convert.py>) извлекает текст из PDF и веб-страниц. PDF без текстового слоя требует отдельного распознавания; сохранённый оригинал сам по себе не означает, что материал доступен поиску.

[Индекс index.py](<index.py>) делит тексты на фрагменты с адресом раздела и страницей. Ранжирование сочетает совпадение слов по BM25 — методу оценки текстовой близости — и близость векторных представлений текста. [Модуль embed.py](<embed.py>) вычисляет векторы моделью `multilingual-e5-small` через ONNX Runtime. Фильтр `as_of` скрывает фрагменты, опубликованные позже даты поиска.

Карточки эпизодов строит [episodes.py](<episodes.py>) по рядам из [series.py](<series.py>): рассчитываются изменение от базы, экстремум и время восстановления. Написанная человеком хронология сохраняется при пересборке численной части, а фактор без истории отмечается как неизмеренный, не как нулевой эффект.

## Команды

Из корня репозитория операции выполняются в уже подготовленном корне корпуса, содержащем манифест и каталог рядов:

```powershell
uv run python -m mst.corpus check --corpus workspace/corpus
uv run python -m mst.corpus fetch --corpus workspace/corpus
uv run python -m mst.corpus convert --corpus workspace/corpus
uv run python -m mst.corpus index --corpus workspace/corpus
uv run python -m mst.corpus search "повышение ставки" --as-of 2026-10-29 --corpus workspace/corpus
```

`check` показывает наличие материалов, `fetch` обращается к адресам источников, а `convert` и `index` записывают производные файлы. Первая подготовка векторного поиска может потребовать загрузки модели представлений текста. Частичная ошибка загрузки возвращает ненулевой код, сохраняя успешно полученные документы; параметры перечислены в [cli.py](<cli.py>).

Остальные операции имеют отдельную цель:

| Операция | Когда нужна |
| --- | --- |
| `add KEY FILE --url URL` | Зарегистрировать вручную полученный оригинал под ключом манифеста |
| `series --store DIR` | Подготовить ряды движений для карточек эпизодов |
| `episodes --store DIR` | Обновить измеренную часть карточек, сохранив ручной текст |
| `eval --questions FILE` | Проверить поиск по вопросам с известными ожидаемыми фрагментами |

Параметр `--corpus` задаёт корень материалов, а `--store` — месячное хранилище рядов для резервного чтения. Исходные объявления и правила наполнения описаны в [руководстве корпуса](<../../../corpus/README.md>), проверочные вопросы лежат в [наборе поиска](<../../../bench/corpus-search/questions.md>). Проверки парсинга и отбора по дате находятся в [tests/corpus](<../../../tests/corpus/README.md>); доступность внешних сайтов такими проверками не подтверждается.
