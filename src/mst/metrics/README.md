# mst.metrics

Метрики качества раздела 5 [схемы](../../../docs/concept/system-scheme.md): как система судит о
версиях моделей на исторических эпизодах.

```powershell
python -m mst.metrics backtest [MODEL_ID] --as-of DATE --store DIR --models DIR --corpus FILE \
  [--drivers FILE] [--satellites] [--only ID ...] [--details FILE] \
  [--against REPORT.json] [--target-level LEVEL] [--portfolio ID] [--mc-bootstrap]
```

| Файл | Что делает |
|---|---|
| `cells.py` | Ячейка $(e,t,q)$: факт, розыгрыши, случайное блуждание, базовый расчёт и наивный прогноз; CRPS (точная оценка по рангам), mid-PIT $\hat F(y)$, полоса, $\sigma_q(t)$ с цепочкой замены и источником, размах истории, баллы ячейки, бутстрэп по эпизодам |
| `aggregate.py` | Равновесный агрегат §5: среднее внутри величины → равный вес величин → среднее по горизонтам, по уровням; бутстрэп агрегата по эпизодам (SE и перцентильный интервал) и вклады эпизодов для wild-проверки; полезность сценария (доля эпизодов с отрицательной разницей против базового расчёта, разрез вручную/LLM); MC-интервал бутстрэпом по розыгрышам |
| `wild.py` | Кластерный wild-бутстрэп с весами Уэбба: проверка каждого интервала при малом числе эпизодов |
| `decision.py` | Правило двух стандартных ошибок: четыре шага §5 на агрегатах целевого уровня |
| `es.py` | Acerbi–Székely $Z$: условные пути эпизода в собственных единицах, фактические пути окна, оценка позиций портфеля через движок, вклады эпизодов, интервалы, trimmed-чувствительность к 1 % крайних путей |
| `baselines.py` | Эталоны: случайное блуждание с дрейфом (пары точного расстояния — gappy-ряды не ломают дрейф) и наивный годовой прогноз; правила допуска; вероятность ограничения в базовом расчёте |
| `episodes.py`, `episodes.toml` | Эпизоды: переменные, шоки, окно, исключения; половина `half` и источник сценария `source` у каждого; дата расчёта — день до начала |
| `backtest.py` | Раннер: версии моделей, ячейки, гейты, интервалы (пара + wild), агрегат §5 с разрезами, полезность, половины, вердикт `--against`, хвост `--portfolio`, метаданные воспроизводимости |
| `cli.py`, `__main__.py` | Команда `python -m mst.metrics` |

## Что именно измеряется

- **Ячейка** — эпизод, месяц горизонта, величина. Связанная сценарием ячейка отчитывается, но
  не оценивается: условный прогноз в ней совпадает с фактом.
- **CRPS/$\sigma_q(t)$** — CRPS, делённый на типичное движение величины за $t$ месяцев. И
  $\sigma_q(t)$, и размах истории берутся из истории, известной **на дату расчёта этого
  эпизода**. Если валидной $\sigma_q(t)$ нет — цепочка замены: $\sigma(t^*)$ с ближайшим
  меньшим горизонтом, затем $\sigma(t_+)$ с большим, затем медиана $\sigma_r(t)$ по величинам
  того же уровня; источник каждой $\sigma$ и число пар, на которых она стоит, записаны в строке
  ячейки (`sigma_source`, `sigma_pairs`). Для величин с квартальным усреднением шаг «месяц»
  остаётся календарным.
- **Равновесный агрегат** (§5) — сначала среднее по эпизодам внутри величины на месяце $t$,
  затем среднее с равными весами по величинам уровня (вес величины равен 1 независимо от числа
  её ячеек), затем среднее по горизонтам. Считается отдельно по каждому уровню и отчётся
  таблицей «уровень × горизонт»; разрез половин — рядом, итоговая таблица — по всем эпизодам.
  Целевой уровень вердикта и полезности — `--target-level` (по умолчанию `macro`; с
  `--satellites` можно назвать уровень драйверов, например `driver/share_price`).
- **Полезность сценария** (§5) — доля эпизодов, где CRPS условного прогноза ниже CRPS базового
  расчёта, и средняя разница; разрез по `source` эпизода (вручную/LLM). Пока все сценарии
  размечены вручную, столбец LLM присутствует, но непоказателен.
- **Допуск** — два правила, каждое со своей долей **по всем оценённым ячейкам**: полоса внутри
  области значений величины и ширина полосы не больше размаха истории. Версия проходит, если
  каждая доля меньше 5 %; объединение правил и разбиение по величинам в приговор не идут (они
  отчитываются справкой). Те же доли и гейт считаются отдельно по каждой половине.
- **$\pi_c$** — доля путей базового расчёта, выполняющих ограничение; гейт $\pi_c>1\%$. У
  эпизода, восстановленного по факту, ограничения точечные ($low=high$), и непрерывный розыгрыш
  попадает в точку с вероятностью ноль: там $\pi_c$ помечается как **неприменимая** и из гейта
  исключается, а не печатается нулём. Для интервальных ограничений гейт настоящий.
- **Интервалы** — три разных, и в отчёте они подписаны. Интервал выборки: 95 % бутстрэп по
  эпизодам, 1000 повторений, `seed` из `episodes.toml`; пересэмплируется **та же статистика, что
  в отчёте** — равновесный агрегат целевого уровня, а SE этого бутстрэпа читает правило 2 SE.
  Wild-интервал: те же вклады эпизодов перевешиваются весами Уэбба, рядом — флаг расхождения;
  при числе эпизодов меньше восьми он читается как основной, потому что обычный бутстрэп там
  занижает интервал. С `--mc-bootstrap` — отдельный интервал бутстрэпом по розыгрышам: ошибка
  Монте-Карло отчитывается отдельно от ошибки выборки по эпизодам.
- **Вердикт** (`--against REPORT.json`) — четыре шага §5 по целевому уровню: допуск, улучшение
  против эталона и текущей версии более чем на 2 SE при неухудшенных долях допуска, отклонение
  при регрессии, иначе «различие не обнаружено». Оба отчёта проверяются на одних и тех же
  ячейках: неполная пара — ошибка с перечнем, а не сравнение на пересечении; ячейки без
  нормированного балла в одном из отчётов считаются и называются, а не сужают сравнение молча.
  Вердикт считается на половине проверки и называет её.
- **Хвост** (`--portfolio ID`, требует `--satellites`: позиции оцениваются на путях
  драйверов) — Acerbi–Székely $Z=\frac{1}{0{,}05n}\sum_e \ell_e\mathbf
  1\{\ell_e>\mathrm{VaR}_e\}/\mathrm{ES}_e-1$ по эпизодам с реализованной потерей. Предиктивные
  $\mathrm{VaR}_e$ и $\mathrm{ES}_e$ — P95 и ES95 потерь портфеля на условных путях эпизода
  (через движок), $\ell_e$ — потеря портфеля между фактами $t=0$ и $t=H$ окна (допущение 8
  плана). В отчёте: интервал по эпизодам, wild-интервал, $Z$ на усечённых 1 % крайних
  розыгрышей, пометка горизонта и поимённо выпавшие эпизоды. Вердикт допуска $Z$ не читает.
- **Сателлиты** — доля путей вне диапазона **обучающей выборки** узла должна быть меньше 1 %;
  границы записываются в часть версии при оценке (`train_low`/`train_high`). Версия без
  записанных границ (старая часть) проверяется по всей колонке и помечается
  `legacy_training_range`. Непроверенный хвост помечается у величины в отчёте.

## Чего здесь нет

- Уровни $L>1$ и обратная задача (фаза 4 плана) — вне объёма этой реализации; канон их
  описывает, код ограничен $L=1$.
- Сценарии от LLM: разрез `source` есть, но размеченных LLM эпизодов пока нет, и полезность
  LLM надёжна только в расчётах вперёд от даты формализации.
- Альтернативные определения $\operatorname{dist}(P_s,P)$ (расстояние Вассерштейна,
  эмпирическая KL) — только перечислены; реализовано платформенное $-\log\mathrm P(C)$.
- Покрытие и резкость — справка, а не цель.

## Кэш

Версии эпизодов пишутся в `<models>/backtest/`; ключ кэша макро-версии включает данные на дату
расчёта, конфигурацию пакета модели (`spec.toml`, `signs.toml` и код), реестр макро-переменных
и версию model SDK, поэтому правка конфигурации не переиспользует старую версию. Ключ кэша
сателлитов — `satellites-<digest>`: имя макро-версии, байты каталога драйверов, их ряды на дату
расчёта, конфигурация и версии сателлитных плагинов, версия plugin SDK, назначения величин.
Старые указатели `satellites-<имя макро-версии>` не переиспользуются и удаляются при встрече.
