# mst.metrics

Каркас качества раздела 5 [схемы](../../../docs/scenario-formalization.md): как система
судит о версиях моделей на исторических эпизодах.

```powershell
python -m mst.metrics backtest [MODEL_ID] --as-of DATE --store DIR --models DIR --corpus FILE \
  [--drivers FILE] [--satellites] [--only ID ...] [--details FILE]
```

| Файл | Что делает |
|---|---|
| `cells.py` | Ячейка $(e,t,q)$: факт и розыгрыши; CRPS (точная оценка по рангам), $u=\hat F(y)$, полоса, типичное движение $\sigma_q(t)$, баллы ячейки и бутстрэп по эпизодам |
| `baselines.py` | Эталоны: случайное блуждание с дрейфом, наивный годовой прогноз; правила допуска (область значений, размах истории) и вероятность ограничения в базовом расчёте |
| `episodes.py`, `episodes.toml` | Эпизоды: связанная переменная, движущие шоки, окно, исключения; дата расчёта — день до начала |
| `backtest.py` | Раннер: версия макромодели на день до эпизода (кэш по состоянию данных), сценарий из случившегося, ячейки по несвязанным переменным и (с `--satellites`) драйверам, таблицы и полный отчёт |
| `cli.py`, `__main__.py` | Команда `python -m mst.metrics` |

Версии эпизодов пишутся в `<models>/backtest/`, отдельно от версий workspace. Acerbi–Székely
для хвостов, кластерный wild-бутстрэп и деление эпизодов на половины — следующие итерации
каркаса.

Тесты — [../../../tests/metrics](../../../tests/metrics/).
