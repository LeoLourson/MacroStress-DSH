# mst.metrics

Проверка моделей на исторических эпизодах. Модели откатываются к дате перед началом прошлого
события и на данных, известных только к этой дате, предсказывают то, что случилось. Прогноз
сравнивается с фактом по каждой величине и каждому месяцу горизонта, поэтому видно не только
«в среднем неплохо», но и где именно модель ошибается.

Что сравнивается и по каким правилам, описано в [общей схеме
системы](../../../docs/concept/formalization.md), раздел «Метрики качества». Здесь о том, как
это устроено в коде и как читать отчёт.

```powershell
python -m mst.metrics backtest [MODEL_ID] --as-of DATE --store DIR --models DIR --corpus FILE \
  [--drivers FILE] [--satellites] [--only ID ...] [--details FILE] \
  [--against REPORT.json] [--target-level LEVEL] [--portfolio ID] [--mc-bootstrap]
```

## Слова, без которых отчёт не прочесть

**Эпизод** — прошлое событие, для которого записан сценарий: какие переменные заданы фактом,
какими шоками событие объясняли, по каким источникам. Дата расчёта — день перед началом
эпизода; модели оцениваются заново на данных этой даты и подсмотреть будущее не могут. Список
эпизодов — [episodes.toml](episodes.toml). Эпизод — данные, а не часть модели, и набор растёт
по мере разбора новых событий.

**Ячейка** — эпизод, месяц горизонта и величина. У ячейки есть факт и распределение прогноза.
Ячейки одного эпизода зависимы: это одна модель, одни данные и один сценарий, поэтому доли
считаются по ячейкам, а интервалы — по эпизодам. Ячейка, значение которой сценарий задаёт
точно, прогноз в ней повторяет факт и ничего не проверяет: она печатается, но в баллы не
входит.

**Половины.** Эпизоды заранее разделены на настройку (`tuning`) и проверку (`validation`).
Разрез по половинам показывает, не подогнан ли вывод под те эпизоды, на которых модели
настраивались; итоговая таблица строится по всем эпизодам.

**Целевой уровень** — уровень, по которому выносят вердикт и считают полезность сценария: по
умолчанию `macro`, с `--satellites` можно назвать уровень драйверов, например
`driver/share_price`.

## Что считается

**CRPS** — расстояние между прогнозным распределением и фактом. Штрафует и смещение, и лишнюю
ширину; меньше — лучше, ноль — точное попадание.

**Нормировка.** Чтобы сравнивать величины в разных единицах, CRPS делится на типичное движение
величины за тот же горизонт — медиану абсолютного изменения за $t$ месяцев по истории. Если
истории на горизонт не хватает, $\sigma_q(t)$ берётся с ближайшего меньшего горизонта, затем с
большего, затем медианой по величинам уровня; источник и число пар записаны в строку ячейки
(`sigma_source`, `sigma_pairs`), чтобы было видно, на чём стоит нормировка. Для величин с
квартальным усреднением шаг «месяц» остаётся календарным.

**Эталоны.** На тех же ячейках считаются двое: случайное блуждание с дрейфом (для всех величин)
и наивный прогноз — значение годом ранее с трендом (для целевых показателей). Модель должна
быть лучше эталона, иначе она не добавляет ничего к простому «завтра как вчера».

**Базовый расчёт** — тот же расчёт без ограничений, шоков и воздействий, то есть безусловный
прогноз модели на эпизоде. Сценарий полезен, если прогноз при сценарии точнее базового
расчёта.

**Допуск.** Версия допускается к сравнению, если меньше 5 % оценённых ячеек нарушают каждое из
двух условий: полоса $[p_5,p_{95}]$ лежит в области допустимых значений величины и ширина
полосы не больше размаха её истории. Доли каждого правила считаются отдельно; объединение
правил и разбиение по величинам идут справкой.

**Вероятность ограничения.** Сценарий не должен держаться на редком хвосте: для каждого
ограничения считается доля путей базового расчёта, где оно выполняется, и эта доля должна быть
выше 1 %. У эпизода, восстановленного по факту, ограничение точечное, а непрерывный розыгрыш
попадает в точку с вероятностью ноль: там доля помечается как неприменимая и из проверки
исключается.

**Калибровка и резкость.** При верной калибровке факт попадает в полосы ниже $p_5$, от $p_5$
до $p_{50}$, от $p_{50}$ до $p_{95}$ и выше $p_{95}$ с долями 0,05 / 0,45 / 0,45 / 0,05;
отклонение говорит, что модель смещена. Резкость — медианная ширина полосы; она имеет смысл
только при пройденной калибровке, поэтому отчитывается рядом.

**Агрегат.** Общий балл, в котором каждая величина уровня весит одинаково, сколько бы ячеек у
неё ни было: сначала среднее по эпизодам внутри величины на месяце $t$, затем среднее по
величинам уровня, затем по горизонтам. Иначе величина с длинной историей перевесила бы
остальные. В отчёте — таблица «уровень × горизонт» для модели, случайного блуждания, базового
расчёта и наивного прогноза, с двумя разницами (со случайным блужданием и с базовым расчётом) и
разрезом половин.

**Полезность сценария** — доля эпизодов, где прогноз при сценарии эпизода точнее базового
расчёта, и средняя разница. Разрез по разметке (`manual` / `llm`): все эпизоды в
[episodes.toml](episodes.toml) размечены вручную, поэтому столбец LLM пуст. Сценарий от LLM
надёжен только для событий позже даты его записи: модель помнит исход прошлых эпизодов.

**Интервалы** — три вида, в отчёте подписаны:

- по эпизодам — 95 % бутстрэп той же статистики, что в отчёте: 1000 повторений, `seed` из
  `episodes.toml`; стандартную ошибку этого бутстрэпа читает вердикт;
- wild — те же вклады эпизодов, перевешенные весами Уэбба, рядом флаг расхождения; при числе
  эпизодов меньше восьми он читается как основной, потому что обычный бутстрэп там занижает
  интервал;
- по розыгрышам (`--mc-bootstrap`) — ошибка Монте-Карло отдельно от ошибки выборки по
  эпизодам.

**Вердикт** (`--against REPORT.json`) — сравнение кандидата с текущей версией по двум
стандартным ошибкам:

1. не прошла допуск — отклоняется независимо от CRPS;
2. лучше эталона и текущей версии больше чем на 2 SE при неухудшенных долях допуска —
   принимается;
3. хуже текущей версии больше чем на 2 SE — отклоняется;
4. иначе различие не обнаружено, остаётся текущая версия.

Оба отчёта сверяются по ячейкам: неполная пара — ошибка с перечнем, а не сравнение на
пересечении; ячейки без нормированного балла учитываются и называются. Вердикт считается на
половине проверки и называет её.

**Хвост портфеля** (`--portfolio ID`, требует `--satellites`) — проверка того, не занижает ли
модель экстремальные потери. Статистика $Z$ Acerbi–Székely: при верном хвосте её среднее равно
нулю, $Z>0$ значит, что хвост занижен. Предиктивные $\mathrm{VaR}$ и $\mathrm{ES}$ — это P95 и
ES95 потерь портфеля на условных путях эпизода; реализованная потеря — изменение стоимости
портфеля на фактах в начале и в конце окна. В отчёте: интервал по эпизодам, wild-интервал, $Z$
на усечённых 1 % крайних розыгрышей, пометка горизонта и поимённо выпавшие эпизоды. Допуск $Z$
не читает.

**Выход за обучающую выборку.** Доля путей сателлита вне диапазона обучающей выборки узла
должна быть меньше 1 %. Границы записываются в версию при оценке (`train_low` / `train_high`);
часть без них не читается. Величина с непроверенным хвостом помечается в отчёте.

## Что печатает отчёт

| Раздел | Что в нём |
|---|---|
| Episodes | Эпизоды: дата расчёта, горизонт, заданные переменные, шоки, худшая вероятность ограничения |
| Admission | Два правила допуска: сколько ячеек нарушено, какая это доля, какие эпизоды виноваты |
| Aggregate | Таблица «уровень × горизонт»: модель, случайное блуждание, базовый расчёт, наивный прогноз и две разницы — со случайным блужданием и с базовым расчётом |
| Scenario usefulness | Полезность сценария по источнику разметки |
| Halves | Те же агрегаты по половинам настройки и проверки |
| Quantities | Величины: нормированный CRPS, эталоны, калибровка, резкость, доли допуска |
| Decision | Вердикт по двум стандартным ошибкам, с `--against` |
| Tail | $Z$, интервалы, усечение, выпавшие эпизоды, с `--portfolio` |
| Reproducibility | Версии моделей и данных, дата, seed, коммит |

Отчёт печатается таблицами Markdown в stdout; полный отчёт со всеми величинами и ячейками
пишется в файл `--details`. Код выхода 1 — какой-то эпизод не проверен (нет в манифесте,
короткая история, недопустимый сценарий) или нарушено условие допуска.

## Кэш

Версии эпизодов пишутся в `<models>/backtest/`. Ключ макро-версии включает данные на дату
расчёта, конфигурацию пакета модели (`spec.toml`, `signs.toml` и код), реестр макро-переменных
и версию model SDK, поэтому правка конфигурации не переиспользует старую версию. Ключ
сателлитов — `satellites-<digest>`: имя макро-версии, байты каталога драйверов, их ряды на дату
расчёта, конфигурация и версии сателлитных плагинов, версия plugin SDK, назначения величин.

## Чего здесь нет

- Сценарии от LLM: разрез `source` есть, эпизодов с `source = "llm"` нет.
- Покрытие и резкость — справка, а не цель.
- Проверка хвоста цены на редких событиях: на месячной истории в 20 лет событие
  вероятности 1 % ожидается 2–3 раза, и таблица групп по $\pi$ говорит об этом сама;
  отчёт не строит по нему вердикта.

Уровни $L>1$ и обратная задача больше не отсутствуют: бандл симулирует по уровням
(`mst.drivers.bundle`), обратная задача — `mst.scenario.reverse`. Равномерность $u$
считается по расчёту без названных причин, чувствительность к выбору причин — блок
`cause_sensitivity`; rolling-блок (равномерность при $s_0$ по всем датам и проверка
цены на семействе событий `[[price_events]]`) появляется, когда план несёт `[rolling]`.

## Устройство пакета

| Файл | Что делает |
|---|---|
| `cells.py` | Ячейка $(e,t,q)$: факт, розыгрыши, случайное блуждание, базовый расчёт и наивный прогноз; CRPS точной оценкой по рангам, mid-PIT $\hat F(y)$, полоса, $\sigma_q(t)$ с цепочкой замены и источником, размах истории, баллы ячейки, бутстрэп по эпизодам |
| `aggregate.py` | Агрегат: среднее внутри величины → равный вес величин → среднее по горизонтам, по уровням; бутстрэп агрегата по эпизодам (SE и перцентильный интервал) и вклады эпизодов для wild-проверки; полезность сценария; интервал Монте-Карло бутстрэпом по розыгрышам |
| `wild.py` | Кластерный wild-бутстрэп с весами Уэбба: проверка каждого интервала при малом числе эпизодов |
| `decision.py` | Правило двух стандартных ошибок: четыре шага на агрегатах целевого уровня |
| `es.py` | Acerbi–Székely $Z$: условные пути эпизода в собственных единицах, фактические пути окна, оценка позиций портфеля через движок, вклады эпизодов, интервалы, чувствительность к усечению 1 % крайних путей |
| `baselines.py` | Эталоны: случайное блуждание с дрейфом (пары точного расстояния — gappy-ряды не ломают дрейф) и наивный годовой прогноз; правила допуска; вероятность ограничения в базовом расчёте |
| `episodes.py`, `episodes.toml` | Эпизоды: переменные, шоки, окно, исключения; половина `half` и источник сценария `source` у каждого; дата расчёта — день до начала |
| `backtest.py` | Расчёт: версии моделей, ячейки, проверки допуска и ограничений, интервалы (по эпизодам и wild), агрегат с разрезами, полезность, половины, вердикт `--against`, хвост `--portfolio`, метаданные воспроизводимости |
| `cli.py`, `__main__.py` | Команда `python -m mst.metrics` |

Тесты — [../../../tests/metrics](../../../tests/metrics/).
