# mst: от события к показателям объекта

Пакет `mst` содержит сервер MacroStress и расчётную платформу. Сценарий описывает событие, модели строят совместные траектории показателей, а модели позиций переводят траектории в изменение стоимости портфеля. Совместная траектория содержит значения всех величин для одного случайного исхода, поэтому зависимости между позициями сохраняются при сложении потерь.

Сервер использует Model Context Protocol (MCP) — протокол, по которому агент вызывает инструменты программы. Агент выбирает операции и готовит сценарий; численные модели выполняют расчёт. Сценарий утверждает человек, причём выбранные версии моделей, горизонт и число траекторий относятся к запросу расчёта, а не к описанию события.

![Событие, сценарий, модели и результат](<../../docs/images/event-to-result.ru.svg>)

Схема иллюстрирует порядок работы без числового результата: источники обосновывают сценарий, человек утверждает сценарий, а выбранные версии моделей дают условный прогноз и отчёт.

## Какие пакеты читать

Пакеты разделены по ответственности в расчёте. Макропеременная описывает экономику в целом; драйвер — величину конкретного объекта, например цену акции; сателлитная модель связывает драйвер с более общими показателями.

| Ответственность | Пакет |
| --- | --- |
| Загружать и хранить месячные значения с датами публикации | [data](<data/README.md>) |
| Задавать макропеременные и собирать историю, известную на дату | [macro](<macro/README.md>) |
| Находить объекты, готовить историю драйверов и собирать их модели | [drivers](<drivers/README.md>) |
| Хранить источники события и искать доступные на дату фрагменты | [corpus](<corpus/README.md>) |
| Проверять описание события и строить пути при его условиях | [scenario](<scenario/README.md>) |
| Определять договор между платформой и макро-/сателлитной моделью | [model_sdk](<model_sdk/README.md>) |
| Определять входы и результаты модели стоимости позиции | [plugin_sdk](<plugin_sdk/README.md>) |
| Находить подключённые модели по их объявлениям | [plugins](<plugins/README.md>) |
| Оценивать модели и публиковать сохранённые версии | [models](<models/README.md>) |
| Подбирать модель позиции, готовить входы и проверять результат | [engine](<engine/README.md>) |
| Хранить портфель и собирать потери, покрытие и предупреждения | [portfolio](<portfolio/README.md>) |
| Проверять качество прогнозов на исторических эпизодах | [metrics](<metrics/README.md>) |

Общий порядок зависимостей показан в [архитектуре](<../../docs/concept/architecture.md>). Таблица описывает ответственность, а не запрещает любые импорты между соседними пакетами: точные границы проверяются тестами и контрактами расширений.

## Что связывает пакеты

[Сервер mcp.py](<mcp.py>) разбирает запросы инструментов, а длительные операции передаёт [менеджеру задач jobs.py](<jobs.py>). Задача работает отдельным процессом, пишет журнал и занимает именованный ресурс, чтобы две операции не меняли одни данные одновременно. [Модуль store.py](<store.py>) задаёт рабочие каталоги и атомарную запись; [versions.py](<versions.py>) сохраняет метаданные и массивы моделей под хешем содержимого.

[Модуль runs.py](<runs.py>) связывает сценарий, версии моделей, позиции и отчёт в один расчёт. В его выходах отделены пути, прогноз показателей, результаты позиций и отчёт портфеля. Работа с файлами пользовательского рабочего каталога не входит в обязанность модели позиции: модель получает подготовленные входы и пути через контракт.

Из корня репозитория можно проверить доступные команды без загрузки данных:

```powershell
uv run python -m mst.mcp --help
uv run python -m mst.models catalog
uv run python -m mst.plugin --help
```

`catalog` перечисляет установленные модели, но не свидетельствует об их точности. Для изменения пакета выберите его README, затем соответствующий набор из [карты тестов](<../../tests/README.md>); математические требования к сценарию и цене заданы в [общей схеме стресс-тестирования](<../../docs/concept/formalization.md>).
