# Политика безопасности MacroStress

Если вы обнаружили возможную уязвимость MacroStress, отправьте конфиденциальное сообщение
через GitHub: вкладка Security → Report a vulnerability. Пока уязвимость не исправлена,
не открывайте публичный issue. Сообщение должно объяснять, как воспроизвести проблему и
какие возможности получает нарушитель; необычный результат финансового расчёта сам по
себе не означает уязвимость.

## Какие версии получают исправления

Исправления получает последний выпуск MacroStress. Версии до 0.1.0 не поддерживаются;
политика не обещает исправления для всех промежуточных или старых выпусков. Номер версии
вашей установки укажите в сообщении, чтобы сопровождающий мог определить затронутый код.

## Что включить в сообщение

Для проверки нужны версия MacroStress, платформа, минимальный воспроизводимый пример и
описание последствий атаки. Пример должен содержать достаточно шагов и входных данных,
чтобы сопровождающий повторил проблему, но не должен раскрывать рабочие ключи доступа или
чужие персональные данные.

Сопровождающий отвечает в течение недели. Если сообщение подтверждает уязвимость, за
проверкой следуют исправление и выпуск; отдельный срок исправления политика не задаёт.

## Какие границы защищает проект

MacroStress работает локально и получает сведения из внешних источников по защищённому
протоколу HTTPS. Основные места, где недоверенные данные входят в программу, перечислены
по способу взаимодействия:

- Загрузчик корпуса разбирает PDF и таблицы Excel по адресам из
  [манифеста корпуса](<corpus/manifest.json>), а при поиске оригинала переходит по ссылкам
  страницы. Подменённый манифест или скомпрометированный сайт может передать обработчику
  специально подготовленный документ.
- Загрузчики рядов разбирают ответы Московской биржи, Банка России, Росстата и FRED —
  базы Федерального резервного банка Сент-Луиса. Неверный формат и чрезмерный размер ответа
  должны приводить к ошибке обработки, а не к исполнению содержимого как кода.
- Ключ `FRED_API_KEY` и другие учётные данные пользователь задаёт через окружение. Их нельзя записывать
  в рабочую область, журналы или текст, который передаётся агенту. Обнаруженная утечка
  относится к безопасности проекта.
- Сервер Model Context Protocol (MCP), протокола вызова инструментов, передаёт сообщения
  своему клиенту через стандартные потоки ввода и вывода `stdio` и читает ответы клиента. Сервер доверяет клиенту
  и не открывает сетевой порт; клиент с правом вызова инструментов не считается изолированным
  недоверенным пользователем.

## Что не относится к этой политике

Уязвимости внешних поставщиков данных, клиентов MCP и самого DeepSeek Harness находятся
за пределами ответственности MacroStress. Сообщайте о таких проблемах соответствующему
проекту, не публикуя сведения о ещё не устранённой уязвимости.

Если сценарий даёт числа, отличающиеся от ожидаемых, откройте обычный issue и укажите
идентификатор расчёта. Когда расхождение связано с утечкой секретов, исполнением чужого
кода или иной возможностью атаки, используйте конфиденциальный канал безопасности.
