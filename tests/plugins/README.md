# Проверки подключения моделей

Набор проверяет обнаружение плагинов, согласованность их объявлений и взаимодействие с расчётной платформой. Плагин — Python-пакет, который объявляет свои модели и диапазон совместимости комплекта разработки SDK. Проверка соответствия контракту подтверждает, что платформа понимает входы и результаты расширения; экономическую точность модели нужно проверять отдельно.

## Запуск и тестовые пакеты

Из корня репозитория выполните набор расширений:

```powershell
.venv\Scripts\python.exe -m pytest tests/plugins -q
```

[fakes.py](<fakes.py>) задаёт учебную модель, объявление плагина и демонстрационный случай. Другие проверки создают пакет во временном каталоге, чтобы ошибка его структуры не зависела от установленной пользовательской модели. Для собственного расширения порядок работы описан в [руководстве по плагинам](<../../docs/howto/plugins.md>).

## Какие отказы должны быть заметны

[test_discovery.py](<test_discovery.py>) проверяет обнаружение пакетов и общую проверку объявлений. Повтор идентификатора, чужое пространство имён метрики и несовместимый диапазон SDK должны дать отказ с названием плагина. Несколько сателлитных моделей одной величины допустимы как объявления, но выбор исполнителя при оценке обязан быть однозначным.

[test_conformance.py](<test_conformance.py>) проверяет демонстрационный расчёт через диспетчер платформы. Набор намеренно подставляет ошибку демонстрации, неповторяемый результат и позицию, которую плагин обещает рассчитывать, но не рассчитывает. Проверка должна обнаружить нарушение, а не только успешно импортировать пакет.

[test_boundary.py](<test_boundary.py>) проверяет, что движок не импортирует конкретные плагины и не перечисляет их идентификаторы. Такое правило сохраняет границу: добавление нового типа инструмента должно менять пакет расширения, а не формулу в общем движке.

[test_cli.py](<test_cli.py>) создаёт пакет командой `new`, затем проверяет его через `check` и `demo-run`. Команда демонстрации должна вернуть результаты, а сломанный пакет — назвать проблему. Справка и ответственность реестра описаны в [mst.plugins](<../../src/mst/plugins/README.md>).

Сторонний Python-пакет исполняется с правами процесса; успешное соответствие контракту не делает недоверенный код безопасным. Тесты здесь проверяют форму подключения и поведение демонстраций, а не создают изолированную среду исполнения.
