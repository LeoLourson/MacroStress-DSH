# Опорные пути для проверки переноса сценариев

Каталог хранит неизменяемые образцы расчёта, с которыми [test_golden.py](<../test_golden.py>) сравнивает пути и метаданные после изменения сборщика сценариев. Образец, или golden baseline, закрепляет численное поведение конкретных сохранённых моделей. Он нужен для обнаружения расхождения при переносе формата, но не подтверждает экономическую правильность исходного сценария.

[English version](<README.en.md>)

## Какие входы закреплены

Тест использует сохранённые макроверсии, а не повторную оценку или искусственную модель:

| Модель | Хеш версии |
| --- | --- |
| `bvar.sv` | `51ead9204774f7ef0b4657c4e1a3997c77c584a902ebb6d306c68439977658f8` |
| `msvar.markov` | `ecaa07d09611885aa4f98de116ea4b870fc31caa34788dafea3998e2e9ed57ab` |

Версии относятся к дате расчёта 2026-10-29; панель заканчивается сентябрём 2026 года и содержит 23 переменные. Для каждого случая заданы 256 путей, горизонт 12 месяцев, `seed=20261112` и `inner=1`. `seed` — начальное значение генератора случайных чисел; `inner` — число внутренних путей одной группы параметров и реализации вмешательства. Проверка ожидает массив формы `(256, 13, 23)`, включая начальный месяц сентября 2026 года.

[empty.json](<empty.json>) задаёт пустое событие. [shifts-only.json](<shifts-only.json>) содержит сдвиги ставки и Brent, включая нулевой сдвиг и месяцы за пределами ненулевых значений. [constraints-no-causes.json](<constraints-no-causes.json>) содержит точечное наблюдение ставки и интервал взвешенного межмесячного изменения нефти. Числа имеют основание `assumption`: они выбраны для сравнения алгоритмов, а не взяты из события корпуса; `approved_by` остаётся пустым.

Входы сохранили прежний формат. Тест переводит их через рабочую функцию `read_legacy` с точными координатами панели, затем вызывает рабочий `build` напрямую. Пустой `SatelliteBundle` исключает драйверы и позиции; нулевой хеш сателлитов в старом входе обозначает такой пустой набор, а не опубликованную версию.

## Что сравнивается

Архивы NPZ хранят `macro` — пути в исходных единицах — и `shadow` — скрытые координаты в шкале модели до нижних границ. Парный JSON хранит идентификаторы, календарь, число путей, `seed` и весь блок цены. Проверка сравнивает тип массива, форму и байты, а JSON — без округления чисел, поэтому даже малое численное изменение становится видимым.

У пустого случая и случая с одними сдвигами исторический образец цены равен `null`. Такое ожидание закрепляет представление прежнего расчёта; оно не меняет математическое правило нулевой цены сценария без наблюдений. Исторические цены случаев с наблюдениями записаны в [образце BVAR](<51ead920-constraints-no-causes.json>) и [образце MS-VAR](<ecaa07d0-constraints-no-causes.json>).

Межмесячное логарифмическое выражение оставлено намеренно: обычная линейная сумма уровней цен не выражает тот же смысл. Если перенос не может сохранить выражение точно, расхождение требует разбора и не разрешает заменить исходный случай более простым.

## Как проверить без изменения образцов

Из корня репозитория выполните:

```powershell
.venv\Scripts\python.exe -m pytest tests/scenario/test_golden.py -q
```

По умолчанию тест ищет модели в рабочем каталоге репозитория. Если сохранённой версии нет, тест пропускает проверку и перечисляет недостающие хеши; синтетическая модель не подставляется. Переменная `MACROSTRESS_WORKSPACE` выбирает другой корень, и отсутствие версии в явно выбранном каталоге уже означает ошибку. Полная проверка включает все сочетания моделей и случаев без пропусков.

[capture.py](<capture.py>) создаёт образцы только в пустом месте и отказывается перезаписывать существующие. Команда съёмки не относится к обычной проверке:

```powershell
.venv\Scripts\python.exe -m tests.scenario.golden.capture
```

Пересоздавать ожидания только ради прохождения проверки нельзя: сначала нужно объяснить изменение закона путей и принять новое поведение. Отказ перезаписи защищает сохранённые файлы, но не заменяет такое решение.

## Численное окружение

Историческая съёмка использовала Windows 11 `10.0.26200`, Python `3.12.14`, NumPy `2.4.4` и SciPy `1.17.1`. Байтовые ожидания зависят от численных библиотек и платформы; расхождение в другом окружении нужно исследовать, а не автоматически ослаблять сравнение.

Тест не проверяет драйверы, стоимость позиций и доступность внешних источников. Общие численные и смысловые проверки сценария находятся в [родительском наборе](<../README.md>); опорные пути дополняют их проверкой сохранения прежнего поведения.
