# Проверки макрореестра, панели и версий

Набор проверяет платформенную часть `mst.macro`, которая задаёт показатели экономики, собирает доступную историю и хранит результат оценки. Панель — таблица месяцев и переменных в шкале модели; версия — метаданные и массивы одной оценки с хешем содержимого. Алгоритмы конкретных макромоделей проверяются отдельно, например в [tests/bvar](<../bvar/README.md>).

## Запуск и основные контракты

Из корня репозитория выполните набор макроплатформы:

```powershell
.venv\Scripts\python.exe -m pytest tests/macro -q
```

Для изменения календаря или пропусков начните с [test_panel.py](<test_panel.py>), а для сохранения и загрузки — с [test_version.py](<test_version.py>). Общие правила пакета описаны в [mst.macro](<../../src/mst/macro/README.md>); проверка формы версии не должна зависеть от того, какая модель сейчас выбрана пользователем.

[test_registry.py](<test_registry.py>) проверяет преобразования шкал, имена переменных и соответствие таблицам математической схемы. `identity` сохраняет единицу показателя, а `log100` переводит положительный уровень в сто натуральных логарифмов. Эти шкалы нельзя смешивать при записи сценария или чтении путей.

[test_panel.py](<test_panel.py>) проверяет порядок блоков, начало истории, доступность публикаций на дату и удаление календарной сезонности. Пропуск означает отсутствие известного значения, поэтому проверка не должна подменять пропуск нулём. Дата запуска может быть позже последнего месяца панели из-за задержек публикации.

[test_version.py](<test_version.py>) проверяет обязательные ключи, восстановление панели и передачу чтения плагину, имя которого записано в `meta["model"]`. Тесты также проверяют повтор результата и публикацию версии из хранилища рядов. Отсутствующую модель нельзя заменить другой только потому, что обе возвращают массив одинаковой формы.

## Инструмент и границы вывода

[test_model_tool.py](<test_model_tool.py>) проверяет список и описание версий, выбор `model_id`, задачи оценки на ресурсе `models` и каталог установленных плагинов. Задача — отдельная длительная операция платформы; блокировка ресурса помогает не оценивать конкурирующие изменения одновременно.

Прохождение набора подтверждает правильность подготовки и хранения входов для макромодели. Проверка не оценивает качество прогноза на будущих событиях и не делает ограничение конкретной модели универсальным свойством всех плагинов.
