# Сравнение контекста экспертного опроса

Проверка по явному запросу измеряет токены gateway, не меняя количество, порядок и схемы
вопросов. Это не рабочий LLM-плагин; оценка модели не запускается.

Задать `GATEWAY_BASE_URL`, `GATEWAY_API_KEY`, `ELICIT_BENCH_ROOT` (отдельная папка результатов),
`ELICIT_BENCH_SOURCE` (по умолчанию `workspace`) и при необходимости `ELICIT_BENCH_MODEL`
(по умолчанию `gpt-6-astra`). Запуск:

```powershell
.\.venv\Scripts\python.exe bench/elicitation-context/check.py
```

Скрипт копирует ряды в изолированные рабочие области, получает закон шока и восемь отдельных
откликов через настоящий MCP. Остальные режимы используют этот же записанный закон, чтобы
разницу не создавало другое распределение размера. Исполнитель чисел не задаёт. В сравнении
участвуют совпадающие вопросы об откликах; закон записан отдельно в журнале.

- `history`: вся предшествующая история остаётся в запросах.
- `bounded`: на каждый вопрос новый контекст с полным текущим вопросом.
- `per-variable`: четыре отдельных вопроса о горизонтах одной переменной, затем новый контекст.

Каждый вопрос по-прежнему требует девять чисел. В нём есть закон шока, предыдущие горизонты
этой переменной и один доступный опорный отклик. Очистка истории не гарантирует экономического
качества: отдельно проверяются знаки, условие, единицы, динамика и неопределённость. Три размера
одного шока не означают три независимых шока.

Прерванная проверка продолжается с записанных частей и сохранённой истории режима. Для
429/502/503/504 и тайм-аутов предусмотрено не больше трёх попыток с ограниченной задержкой.
Тайм-аут мог израсходовать токены без сообщения об их количестве: этот расход неизвестен,
а не равен нулю. Не запускать режимы параллельно против одного лимита gateway.

Журналы содержат `prompt_tokens`, `completion_tokens`, сообщённый кеш и числовые ответы,
но не ключи доступа. Экономия токенов не равна денежной экономии: веса входа, выхода, кеша и
цены моделей различаются. Для вывода об устойчивом изменении качества нужны повторные выборки.

MCP-сервер не очищает историю DSH. Измеренная экономия требует нового узкого контекста у
вызывающего агента на проверенной границе. Обычный coding-субагент с полным набором инструментов
родителя может её не воспроизвести.
