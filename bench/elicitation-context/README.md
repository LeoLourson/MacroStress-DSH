# Сравнение контекста при экспертном опросе

Эксперимент сравнивает расход токенов языковой модели при ответах на одни и те же вопросы
о макроэкономическом шоке, меняя только объём сохранённой истории. Скрипт запускают по
явному запросу исследователя: ответы сохраняются в изолированных рабочих областях, рабочий
опрос не меняется, оценка макромодели не запускается. Сокращение контекста нужно проверять
отдельно от экономического качества ответов.

## Какие режимы сравнивает эксперимент

Экспертный опрос просит языковую модель описать распределение размера шока и отклики
показателей — разницы уровней при шоке и без него на заданном горизонте. Для эксперимента
[исполняемый скрипт](<check.py>) использует модель `expert.elicited.rw`, нефтяной шок
`gl.oil` и дату `2026-11-05`. Дата означает, какие сведения
доступны при формировании вопроса, а не день запуска эксперимента.

Скрипт копирует ряды из исходной рабочей области в отдельную область для каждого режима.
Через настоящий сервер Model Context Protocol (MCP) — протокол вызова инструментов —
он получает вопрос о распределении шока и восемь вопросов об откликах. Первый режим
записывает распределение, а остальные получают ту же запись. Благодаря общему распределению
сравнение не смешивает влияние длины истории с изменением размера шока.

| Режим | Какая история остаётся в запросе | Цена выбора |
|---|---|---|
| `history` | Скрипт передаёт всю предшествующую историю режима | Модель видит весь диалог, но входные запросы растут |
| `bounded` | Для каждого вопроса скрипт создаёт новый контекст с полным текущим вопросом | Меньше истории; модель видит только явно переданные связи |
| `per-variable` | Скрипт передаёт историю четырёх вопросов о горизонтах одного показателя, затем начинает контекст заново | Модель видит предыдущие горизонты одного показателя, но не историю других показателей |

Скрипт сохраняет количество, порядок и схему вопросов. Вопрос об отклике требует девять чисел
и содержит распределение шока, предыдущие горизонты того же показателя и один доступный
опорный отклик. Девять чисел описывают неопределённость отклика при трёх размерах одного
шока; размеры не становятся независимыми шоками. Исполнитель вопросов сам числа не задаёт.

## Как подготовить и выполнить эксперимент

Нужны установленное окружение проекта, исходное хранилище рядов и доступ к шлюзу модели.
Шлюз получает тексты вопросов и ответов, поэтому перед запуском проверьте, допустима ли
передача используемых данных выбранному сервису. Задавайте ключ доступа только через
переменную окружения и не включайте его в команды, сохранённые в репозитории.

| Переменная окружения | Назначение |
|---|---|
| `GATEWAY_BASE_URL` | Адрес шлюза, к которому скрипт добавляет `/chat/completions` |
| `GATEWAY_API_KEY` | Ключ доступа к шлюзу |
| `ELICIT_BENCH_ROOT` | Отдельная папка рабочих областей, журналов и результатов эксперимента |
| `ELICIT_BENCH_SOURCE` | Исходная рабочая область с рядами; по умолчанию `workspace` |
| `ELICIT_BENCH_MODEL` | Идентификатор модели у шлюза; по умолчанию `gpt-6-astra` |

Папка результатов должна отличаться от рабочей области проекта, поскольку скрипт создаёт
в ней собственные области опроса. После задания переменных выполните из корня репозитория:

```powershell
.\.venv\Scripts\python.exe bench/elicitation-context/check.py
```

Скрипт выполняет режимы последовательно, чтобы не конкурировать за один лимит шлюза. При
ответах HTTP `429`, `502`, `503`, `504` и тайм-аутах скрипт делает не больше трёх попыток
с ограниченной задержкой. Если выполнение прервано, повторный запуск продолжает работу
с записанных частей опроса и сохранённой истории режима.

## Как читать результаты

Журналы содержат числовые ответы и сообщённый шлюзом расход: `prompt_tokens` для входа,
`completion_tokens` для выхода и `cached_tokens` для повторно использованного входа.
Скрипт не пишет ключи доступа в журналы. В папке результатов скрипт создаёт журналы,
контрольные точки возобновления и итоговую сводку по следующей схеме:

```text
ELICIT_BENCH_ROOT/
  history/, bounded/, per-variable/   изолированные рабочие области
  <режим>-trace.json                 запросы, ответы и сообщённый расход
  <режим>-checkpoint.json            история для возобновления
  summary.json                       сопоставление режимов
```

Сравнивайте совпадающие вопросы об откликах, а распределение шока учитывайте отдельно.
Если режим остановился раньше остальных, общая сумма токенов по неравному числу вопросов
не измеряет экономию. Скрипт предупреждает о неполноте, но исследователь должен проверить
совпадение фактически отвеченных вопросов. Тайм-аут мог израсходовать токены без возврата
сведений о расходе; неизвестный расход нельзя считать нулевым.

При экономической проверке рассмотрите знаки, условие вопроса, единицы, динамику и
неопределённость. [Скрипт описательной оценки](<economics.py>) выводит медианы откликов и
отмечает случаи совпадения квантилей; скрипт не заменяет экспертное решение о качестве.
Экономия токенов не равна экономии денег, поскольку цены входа, выхода и кеша различаются.
Чтобы говорить об устойчивом изменении качества, нужны повторные выборки ответов, а не
одно сравнение режимов.

MCP-сервер не очищает историю DeepSeek Harness — приложения, которое вызывает инструменты.
Новый узкий контекст должен создавать вызывающий агент на границе, проверенной экспериментом.
Субагент для разработки, получивший полный контекст и набор инструментов родителя, может
не воспроизвести измеренное сокращение входа.
